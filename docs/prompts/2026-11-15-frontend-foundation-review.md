# FE 기반 설정 검토와 문서 정리

- 작성일: 2026-11-15
- 관련 이슈 / PR: 미생성

## 목적

미커밋 FE 기반 설정을 검토하고, 최신 이메일 인증 계약과 지속적으로 사용할 작업 지침을 정리한다.

## 핵심 요청

요약: 사용자는 로컬·원격 저장소의 불필요한 파일, 보안 문제, AI 지침과 템플릿의 연결 및 문서 일관성을 검토하도록 요청했다.

요약: 후속 요청으로 이메일 계약 반영, CLAUDE.md의 임시 구현 상태 삭제, 한 줄 AGENTS.md 추가, GitHub 브랜치 보호 설정, BE 링크 수정 및 README 축약을 요청했다. BE의 HTTP 공개 문제는 검토 후 결정하기로 했다.

| -------------------------------------------------- | ---- | ---------------------------------------------------------------- |

| 원격 BE의 이메일 계약으로 타입·중복 확인 목업 갱신 | 채택 | 사용자 확인 및 BE 명세·구현과 일치                               |

## 반영 내용

- 회원 응답을 email·emailVerified·onboarded와 NEW/LIVING 사용자 유형으로 갱신한다.
- 이메일 중복 확인 목업에 정규화·형식·길이 검증과 테스트를 반영한다.
- CLAUDE.md에서 이전 로그인 전제·업로드 구현 예정·구체 버전·날짜 예시·개별 홈 구성 지침을 정리한다.
- AGENTS.md에서 CLAUDE.md를 읽도록 연결한다.
- README를 실행·명령·디렉터리 구조·API 연동·협업 순서로 축약하고 BE 링크를 수정한다.
- Git 제외 상태인 로컬 계획 문서의 이전 인증·접근 정책 설명도 정정한다. 이 문서들을 커밋 대상으로 강제 추가하지 않는다.

## 남은 작업

- 관리자 권한이 있는 계정으로 FE main 보호 규칙을 적용한다. PR·승인 1명·check 통과를 요구하고 force push와 브랜치 삭제를 금지한다. 브랜치 운영 방식은 아래 후속 결정에 따른다.
- 계정 화면과 실제 이메일 인증 연동은 별도 구현·검증한다.
- BE의 HTTP 공개 문제는 사용자 검토 후 결정한다.
- 커밋·PR 생성 후 기록 링크를 확정한다.

## 2026-11-15 후속 결정: 브랜치 운영 단순화

요약: 사용자는 FE 2명 규모에 맞춰 main만 보호하고, 새 작업 브랜치에서 main으로 PR을 보내기로 확정했다. 관련 Markdown을 모두 일치시키고 원격 브랜치를 준비하도록 요청했다. 후속으로 Swagger 링크의 문서 추가를 문의했다.

- 기존 제안인 작업 브랜치 → dev → main의 두 단계 병합은 채택하지 않는다. 최종 흐름은 main → 작업 브랜치 → PR·리뷰·CI → main이다.
- README·CLAUDE.md·로컬 개발 규칙·PR 템플릿 및 CI 트리거를 같은 흐름으로 맞춘다.
- 작성자 외 FE 1명 승인·CI 통과 후 squash merge하고 작업 브랜치를 삭제한다.
- Swagger 주소는 README의 API 연동 절에만 추가한다. 공개 HTTP 주소에는 실제 비밀번호·토큰을 입력하지 않도록 안내한다.
- 현재 기초 설정용 작업 브랜치 이름은 AI가 chore/frontend-setup으로 정하고 로컬에 생성했다. 미커밋 변경은 보존했다. 원격 브랜치 생성·main 보호 설정은 연결 계정의 쓰기·관리 권한 부재로 미적용 상태다.
- 후속 검증: 변경 문서·CI YAML의 Prettier 검사와 git diff --check를 통과했다. 전체 Markdown을 검색해 이전 브랜치 운영 지침이 남지 않았음을 확인했다. Swagger 주소는 인증정보 없이 조회해 HTTP 200과 Swagger UI 페이지를 확인했다. 원격 설정·실제 API 호출 검증은 수행하지 않았다.
