# 회원가입·온보딩 화면 구현

- 작성일: 2026-11-20
- 관련 이슈 / PR: 미생성

## 목적

언어 선택(F01)부터 회원가입(M02b)·로그인(M02a)·비밀번호 재설정(M02c·M02d)·온보딩(F02~F06)·`/home` 자리 화면까지 구현한다.

## 핵심 요청

> CLAUDE.md랑 docs 폴더 읽고, 10절 작업 순서대로 회원가입·온보딩부터 만들어 줘.

요약: 10절은 로컬 인계 문서 `welcome-siheung-handoff/CLAUDE.md`의 작업 순서다. 화면 명세·API는 같은 폴더의 `docs/screens`·`docs/openapi.json`을 기준으로 했다.

## 반영 내용

- API: `ApiError.details` 추가(LOGIN_FAILED 시도 횟수), 본문 없는 202 응답 처리, `MemberResponse`에 온보딩 답 필드 추가.
- 라우트 가드: `['me']` 쿼리로 비로그인·온보딩 전·완료 상태를 나눈다. 401은 비로그인(null)으로, 그 외 실패는 다시 시도 화면으로 처리한다.
- 언어: F01·상단바 선택을 즉시 반영하고 로그인 전 선택을 sessionStorage에 표시한다. 로그인 시 그 선택이 있으면 `PATCH /api/members/me`로 맞추고, 없으면 계정 언어를 쓴다. 가입 인증 메일·가입 요청에 언어를 보낸다.
- 로그인·가입·로그아웃·재설정 성공 후 CSRF 토큰을 다시 받는다.
- 온보딩 답은 기능 범위 Context와 sessionStorage(회원 ID 기준)에 두고 F06에서 `PUT /api/members/me/onboarding`으로 한 번에 저장한다. 건너뛴 항목은 null·빈 배열로 보낸다.
- 공통 UI: MobileFrame(480px), TopBar, LanguageSelect, Button, TextField, ChoiceCard, StepHeader, Notice. 색은 디자인 시스템 토큰을 CSS 변수로 정의했다. 오류 빨강·성공 초록은 토큰에 없어 임시값이다.
- MSW 목업을 가입·로그인·재설정·온보딩·언어 변경까지 확장했다. 고정 인증 코드 `123456`, 재설정 토큰 `mock-reset-token`, 기존 회원 `taken@example.com`을 쓴다.

## 2026-11-20 수정: 재설정 링크 확인 오류

요약: 사용자가 메일 링크 주소를 `http://localhost:5173`으로 바꿔 열었더니 M02d에서 알 수 없는 오류 화면이 나왔다고 보고했다.

- 원인: 링크 확인 API의 204(본문 없음)를 `undefined`로 돌려줬고, TanStack Query가 `undefined` 데이터를 오류로 처리했다. MSW 계약 테스트는 API 함수만 호출해 이 문제를 잡지 못했다.
- 수정: 확인 성공 시 `true`를 반환한다. 토큰이 쿼리 키를 통해 오류 로그에 남아 쿼리 키에서 토큰을 빼고, 토큰마다 컴포넌트를 다시 마운트한다.
- 확인 중 개발 서버 로그의 재설정 토큰이 마스킹되지 않고 AI 출력에 노출됐다. 해당 링크는 쓰지 않고 새로 요청하도록 안내했다.
- 원인 메모: 팀 서버의 메일 링크 주소는 `http://34.22.97.3`(80번 포트)이고, 해당 주소에 프론트엔드가 배포돼 있지 않아 열리지 않는다. FE 저장소에는 CI만 있고 배포(CD)가 없다.
- 검증: typecheck·lint·Vitest 54개 통과. 수정 후 사용자 보고·스크린샷: 새 링크(주소를 `http://localhost:5173`으로 바꿔 열기)로 M02d 표시, 비밀번호 변경, 새 비밀번호 로그인 성공.

## 2026-11-20 후속: 챗봇 (M08)

> 응, 챗봇부터 만들어 줘

요약: Swagger로 만들 수 있는 화면을 묻는 질문에 AI가 챗봇·내 정보·관리자를 제시하고 챗봇을 추천했다. 사용자가 챗봇을 선택했다. 라이브 Swagger와 인계 openapi.json의 API 29개가 같음을 확인했다.

- 반영: 피그마 M08a~c 기준으로 `/chat`(새 대화·추천 질문), `/chat/:conversationId`(대화), `/chat/history`(이전 대화·삭제 확인)를 만든다. 하단 탭 "질문"을 연결한다.
- 대화는 첫 질문을 보낼 때 만든다(빈 대화가 쌓이지 않게). 질문 실패 시 입력을 돌려주고 자동 재시도하지 않는다.
- 답변 표시: 출처 칩(누르면 쪽수·원문), 자료 없음·AI 오류·담당 기관 안내는 노란 말풍선, 응급은 빨간 119·112 전화 버튼, 개인정보 가림 안내, "도움이 됐나요?" 평가. 서버 문구는 HTML이 아닌 텍스트로만 표시한다.
- 제외: "사진"(고지서 번역, M08d)은 API가 없고, 관련 화면 "자세히 보기"는 연결할 상세 화면이 없어 넣지 않았다. 평가 의견(comment) 입력도 넣지 않았다.
- 수정: 첫 질문 후 주소가 `/chat/1`로 바뀌며 페이지가 다시 마운트돼 입력 포커스가 사라지는 문제를 브라우저 확인 중 발견했다. 선택 경로 하나(`/chat/:conversationId?`)로 같은 페이지를 유지하고, "새 대화"에서 상태를 비우도록 고쳤다.
- MSW 목업: 키워드별 고정 답변(일반·비자 안내·응급·자료 없음)과 6자리 이상 숫자 가림. 실제 RAG가 아니다.
- 검증: typecheck·lint·Vitest 61개·형식·빌드 통과. 목업 서버(5174)와 Chrome으로 질문 3종 표시, 개인정보 가림 안내, 기록 목록, 삭제 확인·삭제를 확인했다(데스크톱 창, 480px 프레임). 실제 BE 챗봇 연동과 4개 언어 화면은 미확인.

> 관리자 화면도 만들어 줘

- 확인: 피그마에 관리자 화면 디자인이 없다. 기존 공통 컴포넌트로 단순한 화면을 만들었다(AI 판단, 디자인 확인 필요).
- 반영: `/admin` 메뉴(내 정보에 관리자일 때만 링크), `/admin/members`(이메일·권한 검색, 확인 후 권한 변경, 자기 행은 버튼 숨김), `/admin/reviews`(사유·처리 여부 필터, 처리 완료·메모 저장), `/admin/guides`(항목 코드·언어로 문구 불러오기·전체 저장, "변경됨" 표시 여부 선택). `RequireAdmin` 가드는 화면용이며 실제 거절은 서버 403이다. 관리자는 온보딩 강제 이동에서 제외했다.
- 항목 목록 API가 없어 문구 화면은 코드를 직접 입력한다. 없는 언어(404 `GUIDE_TRANSLATION_NOT_FOUND`)는 빈 양식으로 열고 저장하면 새로 만든다.
- MSW 목업: 관리자 계정 `admin@example.com`, CL-01 한국어 문구, 회원·검토·문구 API와 비관리자 403.
- 수정: 문구 화면에서 필터용 `flex-basis`가 세로 폼의 높이로 적용돼 입력칸 간격이 벌어지는 문제를 브라우저에서 발견해 고쳤다.
- 검증: typecheck·lint·Vitest 72개·형식·빌드 통과. 목업 서버와 Chrome으로 관리자 링크, 메뉴, 회원 목록, 문구 불러오기를 확인했다. 검토 화면과 저장 동작은 계약 테스트로만 확인했고, 실제 BE 연동과 4개 언어 화면은 미확인.
