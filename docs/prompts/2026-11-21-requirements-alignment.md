# 요구사항 명세 기준 FE·BE 불일치 수정

- 작성일: 2026-11-21
- 관련 이슈 / PR: 미생성

## 목적

노션 요구사항 명세서를 기준으로 Siot-BE와 Siot-FE를 비교해 서로 맞지 않는 부분을 고친다.

## 핵심 요청

> Siot-backend랑 Siot-frontend를 비교해서 둘의 코드가 일치하지 않는 부분을 전부 찾아 고칠 것. 기준은 https://app.notion.com/p/412c12d8513e8022ab87c285bf8129a0 로 진행

## 확인 범위

- FE가 호출하는 API 25개와 BE 컨트롤러 경로·메서드: 모두 일치.
- 요청·응답 필드(회원·인증·온보딩·챗봇·관리자), 열거값, 페이지 응답, 오류 응답·오류 코드: 일치. BE 챗봇 평가 요청의 선택 항목 `comment`는 FE가 보내지 않지만 CB-04가 요구하지 않아 그대로 둔다.
- 노션 M-01~11, CB-01~17, ADM-01~08, CHK-06, COM-01~04, NFR-01~04, NTF-09와 FE 화면 동작: 아래 불일치를 찾았다. BE는 해당 요구사항과 맞았다.

## 선택과 이유

| 검토한 방법                                                      | 선택 | 이유                                                                                                       |
| ---------------------------------------------------------------- | ---- | ---------------------------------------------------------------------------------------------------------- |
| M-02 중복 확인을 코드 발송 응답(409)으로 대신하던 기존 방식 유지 | 제외 | 명세가 입력란의 중복 확인과 결과 표시를 요구한다. 이메일 칸을 벗어날 때 확인하고 결과를 입력란 아래에 표시 |
| 관련 페이지(CB-10)를 상세 경로 링크로 표시                       | 보류 | 체크리스트·생활수칙·행사 상세 화면이 아직 없어 링크가 404가 된다. 지금은 제목만 표시                       |
| 로그아웃·탈퇴 후 `/login` 유지                                   | 제외 | 명세(M-06·M-09)는 메인으로 이동. 로그아웃 상태의 메인인 첫 화면(`/`)으로 보낸다                            |
| 세션 만료(401 `UNAUTHORIZED`)를 화면별로 처리                    | 제외 | 공통 QueryCache·MutationCache에서 내 정보를 비우면 가드가 로그인 화면으로 보내고 로그인 후 돌아온다        |

## 반영 내용

- M-03: 비밀번호 규칙에 '영문·숫자·특수문자만'(BE `PASSWORD_INVALID_CHARACTER`)을 추가해 입력 중 체크 표시와 오류 순서를 BE와 맞췄다.
- M-02: 가입 화면에서 이메일 입력란을 벗어나면 `GET /api/auth/email/availability`로 확인하고 '가입할 수 있는 이메일이에요' 또는 '이미 가입한 이메일'을 표시한다. 이메일을 바꾸면 확인 결과와 보낸 코드를 지운다.
- NTF-09: 내 정보에서 미인증 회원이 가입 이메일로 인증 코드를 받아 인증한다 (`POST /api/members/me/email/verification`, `/confirm`). 오류 문구 `EMAIL_ALREADY_VERIFIED` 추가.
- M-06: 삭제 안내에 '회원 정보·가입 이메일'을 추가했다. 탈퇴 후 메인(`/`)으로 이동해 '탈퇴되었습니다'를 표시한다.
- M-09: 로그아웃 후 메인(`/`)으로 이동한다.
- M-08·M-10: 로그인이 필요한 화면에서 로그인 화면으로 갈 때 원래 경로를 넘기고, 로그인하면 그 화면으로 돌아간다(온보딩 전이면 온보딩 우선). 요청이 세션 만료(401 `UNAUTHORIZED`)로 거절되면 로그인 화면으로 보낸다.
- CB-10·CB-02: 답변의 관련 내용(`relatedPages`) 제목을 표시한다. 오류(ERROR) 답변에는 '다시 물어보기' 버튼을 둔다(COM-04).
- CHK-06(관리자 문구 편집): 입력 길이 제한을 BE와 같게 했다(제목 255자, 준비물 30개·한 줄 255자 등).
- MSW: 미인증 회원 이메일 인증 목업 추가.

## 남은 작업

- 체크리스트·생활수칙·행사 상세 화면을 만들면 관련 내용(CB-10)을 각 상세 경로 링크로 바꾼다. 행사는 `/events/{eventId}`로 합의되어 있다.
