# 홈 맞춤 체크리스트

- 작성일: 2026-11-22
- 관련 이슈 / PR: 미생성. 이전 작업 https://github.com/SiotTUK/Siot-FE/pull/5

## 목적

BE에 추가된 체크리스트 API로 홈(H1·H2)의 "준비 중" 자리를 실제 체크리스트로 채운다.

## 핵심 요청

> 홈 체크리스트부터 만들어 줘. git에 fe의 claude.md를 체크하고 만들어.

요약: 앞서 운영 Swagger(`https://34-22-97-3.sslip.io/v3/api-docs`)가 29개에서 70개 API로 늘어난 것을 확인했고, 사용자가 홈 체크리스트를 먼저 선택했다.

## 선택과 이유

| 검토한 방법                                                     | 선택 | 이유                                                                                                |
| --------------------------------------------------------------- | ---- | --------------------------------------------------------------------------------------------------- |
| 마감일·D-day를 FE에서 계산                                      | 제외 | CLAUDE.md "행정 기한은 BE 계약을 따른다". `deadline`·`dDay`·`dDayText`·진행률을 서버 값 그대로 표시 |
| 알림 배너: 서버 `dDay` 기준 30일 이내 가장 가까운 열린 항목 1개 | 채택 | 체크리스트 규칙표 30일 규칙. 응답에 `homeMode`·`nextTask`가 없어 서버 값으로 고르기만 한다(AI 판단) |
| 체크·해당 없음을 저장 후 갱신                                   | 제외 | 누르면 바로 바뀌게 낙관적으로 반영하고, 끝나면 서버에서 진행률을 다시 받는다. 실패하면 되돌린다     |
| 할 일 상세(M07a)를 함께 구현                                    | 보류 | 요청 범위는 홈 체크리스트. 상세 필드(장소·준비물·수수료 등)는 이미 응답에 있어 다음 작업으로 남긴다 |

## 반영 내용

- `features/checklist`: API·타입(`GET /api/members/me/checklist?language=`, `PUT …/checklist/{code}`), 쿼리 훅(언어별 키, 낙관적 상태 변경), 화면 규칙 함수(선택 항목 묶기, 마감 알림 고르기, 다음 상태), 4개 언어 문구, UI(`ChecklistProgress`, `ChecklistSection`, `ChecklistCard`).
- 카드: 체크박스(완료·해제), 배지, 제목·요약·조건별 문구·근거 법령, 서버 D-day 문구, 해당 없음·취소, 기한 지남 시 ☎1345 안내, 안내 변경 태그, 체류 연장 신청 시작일·강조. 안내(INFO) 항목은 체크박스 없음.
- 홈: 상단 "나에게 필요한 할 일 N개"·진행률, 알림 배너, 내 체크리스트, 생활 준비(선택) 접기·펼치기. 쓰지 않게 된 홈 문구 4개 삭제.
- MSW: 온보딩 답에 따라 항목이 달라지는 체크리스트 목업과 상태 저장(개발·테스트 전용, 기한은 목업이 임의로 만든다).
- 공통: `formatMonthDay` 추가.

## 2026-11-22 후속: 체크 후 카드가 움직이는 문제

> 지금은 체크리스트중에 하나를 누르면 위로 올라가면서 화면이 살짝 어지러운데, 이걸 고칠 방법이 있을까?

- 원인: BE `ChecklistService`가 완료 항목을 맨 뒤로 정렬한다(완료 여부 → 기한 없음 → 마감 가까운 순). 저장 후 목록을 다시 받으면 누른 카드가 뒤로 가고 아래 카드들이 위로 올라왔다. 목업은 이 정렬을 하지 않아 앞선 확인에서 드러나지 않았다.
- 검토(AI 제안): 보는 동안 순서 유지(채택) / 재정렬 애니메이션(제외: 움직임이 남고 코드가 늘어남).
- 반영: 상태 변경 후 서버 값으로 상태·진행률을 갱신하되 화면에 보이던 순서를 유지한다(`keepOrder`). 다시 들어오거나 새로고침하면 서버 순서로 정리된다. 목업도 BE와 같은 정렬을 하도록 맞췄다.
- 검증: `npm run check` 통과(Vitest 88개). 390×844 목업에서 체크 전후 카드 순서·위치·스크롤이 같음을 확인하고, 새로고침 후 완료 항목이 맨 뒤로 가는 것을 확인했다. 실제 BE에서는 미확인.

## 2026-11-24 후속 · PR #8 리뷰 반영

- 관련 PR: https://github.com/SiotTUK/Siot-FE/pull/8
- 요청 요약: 리뷰에서 지적한 다섯 항목을 `feature/checklist/home`에서 수정하고 커밋 전에 결과를 보고한다.
- 회원 ID와 언어를 조회 키에 사용한다. 로그인·로그아웃·세션 만료로 기존 조회가 제거되면 이전 체크리스트 저장 응답에서 캐시를 갱신하지 않는다. 저장 후 현재 언어를 포함한 해당 회원의 조회를 갱신한다.
- 온보딩 답변을 저장하면 해당 회원의 체크리스트를 무효화한다. 홈에 돌아갈 때 캐시된 이전 목록이 표시되지 않도록 구독이 없는 조회는 제거한다.
- 홈에서는 카드 식별자 순서만 보관하고 백그라운드 재조회에도 적용한다. 홈을 다시 열면 서버 정렬을 적용한다.
- 카드와 마감 알림은 서버의 음수 `dDay`를 기준으로 기한 초과 문구를 번역한다. 이전 목업 세션에서 누락된 `checklist` 필드를 초기화한다.
- 검증: `npm run check` 통과(Vitest 89개). Chrome 390×844 목업에서 계정 전환 뒤 지연된 저장 실패, 키보드 저장, 화면 복귀와 홈 재진입 시 정렬, 프로필 수정 후 목록, 이전 목업 데이터, 4개 언어 문구를 확인했다. 로딩·오류·재시도·빈 상태도 목업에서 확인했다. 실제 BE 연동은 미확인이다.
