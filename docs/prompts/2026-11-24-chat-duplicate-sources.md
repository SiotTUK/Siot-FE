# 챗봇 답변 출처 중복 표시 수정

- 작성일 2026-11-24
- 관련 이슈 [SiotTUK/Siot-FE#14](https://github.com/SiotTUK/Siot-FE/issues/14)

## 목적

챗봇 답변의 여러 근거 조각이 같은 문서를 가리킬 때 출처 버튼과 쪽수가 중복 표시되는 문제를 해결한다.

## 핵심 요청

`main`에서 작업 브랜치를 만들고, 문서명과 원문 URL을 기준으로 출처를 묶는다. 문서별 첫 출처의 순서를 유지하고, 겹치거나 이어지는 쪽수를 합친다. 삭제되었거나 식별 정보가 부족한 출처는 개별 표시한다.

## 선택과 이유

| 검토한 방법                               | 선택 | 이유                                                         |
| ----------------------------------------- | ---- | ------------------------------------------------------------ |
| 공통 답변 컴포넌트에서 표시용 출처를 구성 | 채택 | 신규 답변과 대화 기록에 동일한 표시 규칙을 적용할 수 있다.   |
| 문서명과 원문 URL의 조합으로 그룹 식별    | 채택 | 응답에 문서 ID가 없고, 이름이 같은 별도 문서가 있을 수 있다. |

## 반영 내용

- 문서별 버튼을 첫 출처 순서로 표시한다. 버튼을 펼치면 합쳐진 쪽수 범위와 기존 원문 링크를 표시한다.
- 떨어진 쪽수는 같은 버튼 안에서 각각 표시한다. 모바일에서는 상세 항목이 줄바꿈된다.
- 문서 식별과 페이지 범위 병합에 대한 회귀 테스트 3개를 추가한다.

실제 백엔드 연동과 실기기 동작은 미검증이다.

## 2026-11-24 후속 요청

- 출처 버튼을 펼치면 쪽수와 원문 링크가 표시되는 동작을 확인했다. 이전 캡처의 동명 버튼 두 개는 서로 다른 원문 URL을 가진 목업으로 재현한 것이다.
- 한 문서의 전체 쪽수를 오름차순으로 펼쳐서 중복을 제거한다. 예를 들어 같은 문서의 9~10쪽, 10쪽, 12쪽은 출처 버튼 하나에서 `9쪽, 10쪽, 12쪽`으로 표시한다.
- 회귀 테스트의 기대 결과를 개별 쪽수 목록으로 바꿨다. Chrome 390×844 목업에서 신규 답변과 대화 기록에 버튼 하나와 쪽수 세 개가 표시되는 것을 네 가지 언어로 확인했다. 키보드 원문 열기와 URL이 다른 동명 문서의 분리도 확인했다.
- [모바일 재현 화면](assets/2026-11-24-chat-duplicate-sources-mobile.png)은 Chrome 390×844에서 같은 문서의 출처를 펼친 상태다.
- 로컬 Spring Boot 백엔드를 연결해 readiness와 프론트엔드 프록시를 통한 인증 API 응답을 확인했다. Gemini 인증이 설정되지 않아 실제 API에서 문서 출처가 포함된 답변은 미검증이다.

## 2026-11-24 병합 전 리뷰 반영

- 긴 출처 범위를 펼쳤을 때 원문 링크가 화면 아래로 밀리는 문제를 수정했다. 겹치거나 이어지는 범위를 먼저 합치고, 연속 10쪽까지는 개별 쪽수로, 11쪽부터는 범위로 표시한다. 떨어진 쪽수는 각각 유지한다.
- 경계값과 범위 사이의 빈 쪽을 포함한 회귀 테스트를 추가했다. Chrome 390×844 목업에서 `1~500쪽`과 원문 링크가 버튼 바로 아래에 표시되고, `9쪽, 10쪽, 12쪽` 표기도 유지됨을 확인했다.
