# 홈 생활 변화 등록·관리

- 작성일: 2026-11-24
- 관련 이슈 / PR: 미생성. 선행 작업은 https://github.com/SiotTUK/Siot-FE/pull/8

## 목적

홈에서 생활 변화를 등록·수정·삭제하고, 저장한 날짜에 연결된 할 일과 기한을 같은 화면에서 확인한다.

## 핵심 요청

F06a·F06b 시안을 참고해 홈에 생활 변화 등록·관리 기능을 추가하고, 기존 생활 변화 API와 홈 체크리스트를 연결한다. 사용자는 날짜를 저장한 화면에서 관련 할 일을 확인하는 흐름을 선택했다.

## 선택과 이유

| 검토한 방법                              | 선택 | 이유                                                                                    |
| ---------------------------------------- | ---- | --------------------------------------------------------------------------------------- |
| 저장 후 F06b에서 관련 할 일 조회         | 채택 | 사용자 선택. 체크리스트 API가 회원 정보와 저장된 기준일에 맞는 할 일과 기한을 반환한다. |
| 날짜 저장 전에 예상 할 일 표시           | 제외 | 현재 API는 저장된 생활 변화를 기준으로 조회한다.                                        |
| 변경 후 체크리스트 캐시 초기화 및 재조회 | 채택 | 날짜 변경이나 삭제 직후 홈에서 이전 회차의 할 일이 잠깐 보이는 문제를 방지한다.         |

## 반영 내용

- 홈에 여덟 가지 생활 변화 선택 바텀시트를 열고, 등록된 유형별 날짜를 표시한다.
- 날짜 입력 화면에 저장, 수정, 삭제 확인, 관련 할 일과 완료·해당 없음 조작을 연결한다. 이사일 상한은 한국 날짜 기준 오늘이다.
- 생활 변화 목록 캐시는 회원별로 분리한다. 세션 전환 시 이전 저장의 재요청과 캐시 갱신을 막고, 저장 뒤 조회가 실패하면 조회만 재시도한다.
- 네 언어 문구, 계정별 MSW 데이터, 기준일별 체크리스트 계약 테스트를 추가한다.

## 2026-11-24 PR #9 리뷰 반영

PR #9의 리뷰 지적 두 건을 수정한다. 최초 수정 단계에서는 변경 사항을 작업 트리에 남긴다.

- 회원과 생활 변화 유형이 같은 저장·삭제 요청은 순서대로 처리한다. 홈을 거쳐 편집 화면을 다시 열어도 먼저 보낸 요청의 응답이 나중에 저장한 날짜를 덮어쓰는 문제를 막는다.
- 생활 변화 목록의 백그라운드 재조회가 실패해도 기존 폼과 입력값을 유지한다. 오류와 재시도 버튼을 함께 표시한다.
- Node 24.18.0과 npm 11.20.0으로 `npm run check`를 실행했다. 테스트 96개와 빌드가 통과했다.
- Chrome 390×844와 MSW에서 연속 저장의 처리 순서, 백그라운드 조회 실패와 재시도 시 입력값 보존, 기존 등록·수정·삭제 흐름과 네 언어를 확인했다. 이번 수정의 실제 API와 운영 환경은 미검증이다.
