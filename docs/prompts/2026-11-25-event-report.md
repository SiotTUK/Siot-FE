# 행사 상세 오류 신고 접수

- 작성일: 2026-11-25
- 관련 요구사항: COM-01
- 선행 작업: [행사 조회 PR #19](https://github.com/SiotTUK/Siot-FE/pull/19), [챗봇 행사 링크 PR #21](https://github.com/SiotTUK/Siot-FE/pull/21)

## 목적

행사 상세를 보는 회원이 잘못된 내용이나 번역을 인용하고 신고 접수를 확인할 수 있게 한다.

## 핵심 요청

- 행사 상세에서 문제 문구와 신고 사유를 받고 접수 결과를 표시한다.
- 전송 중 중복 제출을 막고, 실패하면 입력값을 유지해 재시도를 지원한다.
- 네 가지 화면 언어와 모바일 대표 흐름을 검증한다.

## 선택과 이유

| 검토한 방법                                                        | 선택 | 이유                                                                                           |
| ------------------------------------------------------------------ | ---- | ---------------------------------------------------------------------------------------------- |
| 행사 상세 안에서 폼 열기                                           | 채택 | 사용자가 문제 문구와 행사 정보를 같은 화면에서 확인할 수 있다.                                 |
| 화면 언어에 맞춰 사유를 보여 주고 서버에는 통일된 한국어 사유 저장 | 채택 | 서버가 사유를 문자열로 저장하므로 관리자 화면에서 같은 분류의 신고를 같은 값으로 받을 수 있다. |

## 반영 내용

- `POST /api/reports`로 행사 ID, 표시한 제목, 인용 문구, 화면 언어, 사유를 전송한다.
- 빈 문구와 사유 미선택을 검증한다. 일반 요청 실패 후에는 다시 제출할 수 있다.
- 행사 신고 MSW 응답과 유효성·요청 본문 테스트를 추가한다.

## 검증

| 확인 항목             | 방법                                     | 결과                                                                                                                                     |
| --------------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 정적 검사·테스트·빌드 | Node 24.18.0에서 `npm run check`         | 타입·린트·포맷·Vitest 141개·프로덕션 빌드 통과. 번들 크기 경고가 출력됐다.                                                               |
| 모바일 신고 흐름      | Chrome 320×800, MSW                      | 네 언어에서 필수 입력 오류와 접수 표시를 확인했다. 두 번 눌러도 요청 한 건만 전송했고, 503 응답 뒤 두 입력값을 유지해 재시도에 성공했다. |
| 키보드 조작           | 인앱 브라우저, MSW                       | Tab으로 신고 버튼과 입력에 접근하고 키보드로 사유를 선택한 뒤 Enter로 접수했다.                                                          |
| 실제 행사 조회        | 로컬 백엔드 임시 계정으로 행사 목록 조회 | 진행·예정 목록과 지난 목록 모두 HTTP 200, 각 0건. 임시 계정 정리 완료.                                                                   |

미검증: 로컬 백엔드에 신고 대상으로 사용할 행사가 없어 실제 신고 접수는 검증하지 못했다.

## 남은 작업

- 관리자 행사 목록·상세·등록은 별도 작업으로 진행한다.

## 2026-11-26 PR #22 리뷰 반영

- 오프라인 신고를 즉시 시도하도록 `networkMode: 'always'`를 적용하고 자동 재시도를 끈 상태를 유지한다. 실패하면 기존 오류 안내를 표시하고 입력값을 유지한다.
- Chrome 320×800에서 MSW로 검증했다. 오프라인 오류가 표시된 뒤 입력값이 유지됐고 제출과 취소가 다시 가능했다. 연결 복구 시 자동 전송이 없었으며 수동 재시도 후 접수 성공을 확인했다.
- Node 26.13.1에서 `npm run check`로 타입·린트·포맷·Vitest 141개·프로덕션 빌드를 확인했다. 빌드에서 번들 크기 경고가 출력됐다.
