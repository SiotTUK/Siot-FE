# BE 2026-11-26 변경분과 FE 계약 맞추기

- 작성일: 2026-11-26
- 관련 요구사항: COM-01, COM-02, CHK-06, CHK-07
- 선행 작업: [행사 오류 신고 PR #22](https://github.com/SiotTUK/Siot-FE/pull/22), BE `main` 커밋 `0a2e5d9`~`ca5e6b6`

## 목적

같은 날 BE에 들어간 입력 검증·번역 재생성 변경 때문에 FE 요청이 실패하거나 화면 안내가 실제 동작과 달라지는 부분을 바로잡는다.

## 핵심 요청

- BE 당일 변경분과 FE `main` 코드를 대조해 맞지 않는 부분을 찾는다.
- 찾은 항목 중 깨짐·동작 변화 다섯 가지를 고쳐 하나의 PR로 올린다. BE에만 있는 신규 기능(행사 카테고리, CAL-02 등)은 범위에서 제외한다.

## 선택과 이유

| 검토한 방법                                               | 선택 | 이유                                                                                                |
| --------------------------------------------------------- | ---- | --------------------------------------------------------------------------------------------------- |
| 신고 사유를 `TRANSLATION`·`CONTENT`·`OTHER` 코드로 전송   | 채택 | BE `ContentReportRequest`가 이 세 값만 받는다. 한국어 사유는 400이 된다.                            |
| 인용 문구 길이를 zod에서 2000자로 검증                    | 채택 | BE 제한과 같고, 서버의 일반 `INVALID_INPUT` 대신 구체적인 안내를 보여 줄 수 있다. 서버 검증은 유지. |
| 행사 제목 스냅샷을 255자로 잘라 전송                      | 채택 | 화면 제목이 길어도 신고가 실패하지 않는다. 비워 보내면 서버가 한국어 제목을 채운다.                 |
| 한국어 문구 편집 시 덮어쓰기 안내 + 다른 언어 캐시 무효화 | 채택 | BE가 ko 저장 시 en/zh/vi를 다시 생성한다. 편집기에 남은 옛 번역으로 덮어쓰지 않게 한다.             |
| 체크리스트 `kind`에서 `RULE` 제거, `GUIDE_NOT_FOUND` 안내 | 채택 | BE 체크리스트는 RULE을 주지 않고 체크도 거절한다. 삭제된 항목 체크 시 화면 언어로 안내한다.         |

## 반영 내용

- `event-report.ts`: 사유 코드 전송, 인용 문구 최대 길이, 제목 스냅샷 255자 제한. MSW 신고 핸들러를 BE 검증과 같게 바꾼다.
- `events/messages.ts`: `events.report.quoteTooLong`, `errors.EVENT_NOT_FOUND`를 네 언어로 추가한다.
- 관리자 문구 편집기: 한국어 선택 시 자동 번역 덮어쓰기 안내를 보여 주고, 저장 후 같은 항목의 다른 언어 조회를 무효화한다.
- 체크리스트: `ChecklistItemResponse.kind`를 `CHECKLIST`·`LIFE_CHANGE_TASK`로 좁히고, 체크 실패가 `GUIDE_NOT_FOUND`면 `checklist.itemGone`을 보여 준다(홈·생활 변화 화면).

## 검증

| 확인 항목             | 방법                    | 결과                                                                 |
| --------------------- | ----------------------- | -------------------------------------------------------------------- |
| 정적 검사·테스트·빌드 | `npm run check`         | 타입·린트·포맷·Vitest 156개·프로덕션 빌드 통과. 번들 크기 경고 출력. |
| BE 계약 대조          | BE DTO·서비스 코드 읽기 | 사유 패턴, 길이 제한, RULE 체크 거절, ko 저장 시 재번역 동작 확인.   |

미검증: 실제 BE 연동 신고 접수, 모바일 화면 촬영. MSW의 관리자 문구 핸들러는 ko 저장 시 재번역을 흉내 내지 않는다.
