# 초기 JS 번들 경로별 분리

- 작성일: 2026-11-26
- 관련 이슈 / PR: [Siot-FE #24](https://github.com/SiotTUK/Siot-FE/issues/24) / [Siot-FE #27](https://github.com/SiotTUK/Siot-FE/pull/27)

## 목적

일반 진입 경로에서 챗봇·생활수칙·관리자 화면 코드가 함께 내려오는 문제를 해결한다. 초기 JS 전송량을 줄이고 Vite의 500 kB 청크 경고를 해소한다.

## 핵심 요청

- 이슈에 정리한 분리 방안을 구현하고 빌드와 화면 동작을 검증한다.
- 전체 변경 줄 수와 프롬프트 히스토리, PR 제목·본문, 커밋 메시지를 준비한다. 추가·삭제 합계가 400줄 이상이면 커밋을 나눠 계획한다.
- 승인 전까지 커밋과 푸시를 보류한다.

## 선택과 이유

| 검토한 방법                                          | 선택 | 이유                                                                                    |
| ---------------------------------------------------- | ---- | --------------------------------------------------------------------------------------- |
| 챗봇·생활수칙·관리자 경로에 React Router `lazy` 적용 | 채택 | 이슈 실험에서 초기 JS를 약 23% 줄였고, URL과 기존 가드를 유지할 수 있다.                |
| 달력·행사·온보딩 등 추가 지연 로딩                   | 보류 | 이슈 실험에서 초기 JS gzip 추가 절감이 약 5 kB여서 이번 작업은 세 기능을 대상으로 한다. |
| 동적 import 실패 화면에서 페이지 새로고침            | 채택 | 이전 배포의 청크를 가리키는 탭도 새 HTML을 받아 현재 파일로 다시 시도할 수 있다.        |

## 반영 내용

- 세 기능의 기존 라우트에서 화면 모듈을 동적으로 가져온다. 경로, 레이아웃과 인증·온보딩·관리자 가드를 유지한다.
- 직접 접근 및 앱 안에서 이동하는 동안 기존 로더를 표시한다. 화면 모듈을 가져오지 못했을 때만 4개 언어로 새로고침을 안내한다.
- 변경 전 빌드에서도 보호 경로에서 로그인 직후 원래 주소를 거쳐 홈으로 이동하는 현상을 재현했다. 로그인 후 이동을 게스트 가드에서 처리해 기존 경로와 쿼리 문자열이 유지되도록 수정한다.

- 재현: 비로그인 사용자가 관리자 링크에 직접 접속하면 관리자 청크가 도착한 뒤에 세션 조회가 시작된다. 생활수칙 CSS 요청이 한 번 실패하면 같은 탭에서 화면을 다시 열어도 실패 화면이 남는다.
- 변경: 경로 요소를 먼저 해석하고 인증·온보딩·역할 가드를 통과한 화면에서만 동적 import를 시작한다. 같은 기능의 경로는 모듈 요청을 공유하고, 로딩 중에는 기존 페이지 로더를 표시한다.
- 복구 결정: 청크 요청 실패 화면에는 수동 새로고침을 유지한다. 실패한 기능에 다시 들어오면 현재 URL에서 문서를 한 번 새로고침한다. 브라우저와 Vite가 실패한 청크 요청을 현재 문서에서 재사용할 수 있어 새 문서에서 요청을 다시 시작해야 한다. 새 문서에서도 실패하면 복구 화면을 표시한다.
- GitHub 리뷰: [인증 확인 순서](https://github.com/SiotTUK/Siot-FE/pull/27#discussion_r4709027254)와 [청크 실패 후 재진입](https://github.com/SiotTUK/Siot-FE/pull/27#discussion_r4709027277)을 인라인으로 게시했다.

### 후속 검증

- Node 24.18.0에서 `npm run check`를 통과했다. 테스트 22개 파일의 153개가 통과했다. 최대 JS 청크는 497.51 kB이며 초기 JS의 gzip 합계는 공통 청크를 포함해 211.34 kB다. 500 kB 빌드 경고가 발생하지 않았다.
- Chrome 390 × 844의 로컬 프로덕션 빌드와 모의 API에서 비로그인 사용자와 일반 회원의 관리자 링크 이동을 확인했다. 관리자 JS 요청 없이 각각 로그인과 홈으로 이동했다. 관리자는 가드를 통과한 뒤 청크를 요청했고, 로그인 흐름에서 원래 주소인 `/admin/members?page=2`로 복귀했다.
- 생활수칙 CSS를 한 번 503으로 응답시킨 뒤 재진입했을 때 복구했다. 반복 실패에서는 자동 새로고침이 반복되지 않았고 서버 응답을 복구한 뒤 수동 새로고침이 동작했다.
- 챗봇 JS의 첫 진입 요청을 404로 응답시킨 뒤 재진입했을 때 챗봇이 복구됐고 대화 기록으로 이동할 수 있었다.
- 영문 화면을 직접 열면 상단 언어 선택에 한국어가 표시되는 현상은 수정 전 PR 빌드에서도 재현했다.
- 실제 API, 운영 배포, 실기기 로딩 시간은 확인하지 않았다. 모바일 캡처는 로컬에 저장했다.
