# 알림 목록과 안 읽은 개수

- 작성일: 2026-11-26
- 관련 이슈 / PR: 미생성. 선행 작업 https://github.com/SiotTUK/Siot-FE/pull/23 (탑바 알림 버튼)

## 목적

1차 로드맵(수지, 11/26)의 알림 첫 흐름을 실제 API로 연결한다. 상단 알림 버튼 → 안 읽은 개수 → 알림 목록 → 개별 읽음 → 배지 갱신(NTF-04).

## 핵심 요청

요약: 사용자가 로드맵의 다음 작업인 알림 화면을 만들자고 했다. 탑바 알림 버튼은 직전 PR #23에서 비활성으로 넣어 두었다.

## 반영 내용

- `features/notifications`: API·타입(BE `NotificationController`·`NotificationResponse` 기준: `GET /api/members/me/notifications?page=&size=20`, `GET …/unread-count`, `PATCH …/{notificationId}/read`), 회원별 조회 키, 읽음 후 목록 항목 교체와 개수 다시 받기, 화면 규칙(종류 묶기: 생활 마감·행사·안내 변경·알림, 날짜 표시, 배지 99+), 4개 언어 문구.
- 탑바 종: `TopBarIconButton`에 링크(`to`)와 숫자(`badge`)를 추가하고 `NotificationBell`로 안 읽은 개수를 보여 준다. 0이면 숫자를 숨긴다. 화면 낭독기는 "알림, 안 읽은 알림 n개"로 읽는다.
- 목록 화면 `/notifications`(Figma M09): 흰 카드, "종류 · 날짜" 뱃지, 안 읽은 알림은 파란 점·굵은 글자·파란 뱃지이고 누르면(키보드 Enter 포함) 읽음 처리된다. 읽은 알림은 회색. 20개씩 더 보기(공통 `InfiniteList`).
- MSW: 회원별 알림 4개(Figma 예시 문구), 읽음 상태 저장, 404 `NOTIFICATION_NOT_FOUND`.
- PR #23에서 넣은 `nav.notifications` 문구는 `notifications.title`로 대체해 지웠다.

실제 BE(2026-11-26, 사용자가 Chrome에서 로그인한 계정, 개발 서버 → 운영 BE): 개수·목록 API 모두 200, 안 읽은 개수 0·알림 0건. 탑바 종은 숫자 없이 표시되고, 종을 누르면 `/notifications`에서 "아직 받은 알림이 없어요"가 나온다.

미검증: 실제 알림이 있는 경우의 목록·읽음 처리·배지 갱신(운영 계정에 알림이 없음), BE가 발송 전(`PENDING`) 알림도 목록에 주는지 여부.

## 2026-11-26 후속: 알림 설정

- 요약: 사용자가 Figma M09 아래쪽 "알림 설정"이 반영됐는지 물었다. AI가 BE 지원 범위를 정리했고, 사용자가 "체크박스 두 개 + 기한 알림 시점 안내 문구, 이메일 끄기·행사 관리는 BE 지원 후" 범위로 결정했다.
- 반영: `GET/PUT /api/members/me/notifications/preferences` 연결. "생활 마감 (세금·체류 연장)"은 `STAY_EXPIRY`·`CHECKLIST_DEADLINE`·`TAX` 세 종류를 한 번에 켜고 끄고(모두 켜져 있을 때만 체크), "안내 내용 변경"은 `NOTICE_CHANGED`. 저장할 때 조회한 `leadDays`를 그대로 보낸다 — BE는 빠지면 0으로 저장한다. "기한 알림 시점 D-7 · D-1"은 BE 스케줄러가 고정한 값이라 글로만 보였다. 저장 실패 시 설정을 다시 읽는다.
- 이어서 사용자 결정으로 "기한 알림 시점 D-7 · D-1" 표시를 뺐다. 바꿀 수 없는 값이라 설정 칸에 둘 이유가 없다는 판단이다. 체크박스 두 개와 안내 문구만 남는다.
- 이어서 사용자가 설정 칸 시안 이미지를 보여 줘 모양을 맞췄다: "알림 설정" 제목을 카드 안으로, 체크박스 대신 오른쪽 토글 스위치. 스위치는 공통 `SwitchField`(체크박스 + `role="switch"`, Tab·Space 동작)로 만들었다. 시안의 이메일로도 받기·기한 알림 시점·신청한 행사 관리 줄은 앞선 결정대로 넣지 않았다. 목업에서 마우스·Space 전환과 새로고침 후 유지를 다시 확인했다(Vitest 165개 통과).
- 미반영: 이메일로도 받기(BE API 없음), 신청한 행사 관리(BE 계약 대기), 전체 읽음.
- 검증: `npm run check` 통과(Vitest 165개, 묶음 규칙·설정 계약 테스트 포함). 390×844 목업에서 마우스 클릭으로 생활 마감 끄기(세 종류 모두 false, `leadDays` 30·7·7 유지), 키보드 Space로 안내 내용 변경 끄기, 새로고침 후 유지, 4개 언어 확인. 실제 BE 설정 저장은 미확인(내일 받을 체류 만료 알림을 끄지 않기 위해 실제 계정 설정은 바꾸지 않았다).

## 2026-11-26 후속: 알림 누르면 이동

- 요약: BE main이 `69d9909`로 갱신되어 알림에 `linkType`·`linkCode`가 붙었다(AI가 처음엔 예전 로컬 BE를 보고 행사 알림이 없다고 잘못 답했다가, 최신 main으로 정정했다). 사용자가 알림을 누르면 이동하는 기능부터 만들자고 했다.
- 반영: `notificationPath`로 이동할 화면을 정한다. 행사(`EVENT`)는 행사 상세 `/events/{id}`, 체크리스트·생활 변화 할 일은 홈 체크리스트 `/home`, 세금(`SCHEDULE`)·개인 일정(`CALENDAR`)은 생활 달력 `/calendar`, 생활수칙(`RULE`)은 목록 `/rules`(BE `RUL-xx` 코드와 FE 생활수칙 코드가 달라서). 알 수 없는 값은 이동하지 않고 읽음 처리만 한다. 이동할 곳이 있는 카드는 링크이고, 안 읽은 알림이면 누를 때 읽음 처리도 한다.
- 다른 담당 영역: 행사 상세의 뒤로가기가 알림에서 왔을 때 알림 목록으로 돌아가도록 `features/events/event-routes.ts`에 `/notifications`를 허용하고 테스트에 추가했다.
- 검증: `npm run check` 통과(Vitest 176개, 이동 경로 10개 경우 테스트 포함). 390×844 목업에서 행사 알림 → `/events/2` → 뒤로 → `/notifications`(배지 3 → 2), 안내 변경 알림 → `/home`, 체류 만료 알림을 키보드 Enter로 → `/calendar`, 모두 읽은 뒤 배지 사라짐 확인. 실제 BE 알림으로는 미확인(운영 계정 알림 0건).

## 2026-11-27 후속: 읽음 실패 안내 (PR #25 리뷰 P2)

- 요약: 사용자가 리뷰 지적을 가져왔다. 이동할 곳이 있는 알림은 읽음 요청이 끝나기 전에 이동해, 실패해도 오류를 보여 줄 목록이 이미 사라지고 알림·배지는 안 읽음으로 남았다.
- 반영: 안 읽은 알림은 읽음 처리가 성공한 뒤에만 이동한다. 실패하면 목록에 남아 "읽음으로 바꾸지 못해 이동하지 않았어요. 다시 눌러 주세요."와 실패 이유를 보여 주고, 다시 누르면 재시도한다(4개 언어). 처리 중인 카드는 흐리게 보이고 다시 눌러도 무시한다. 새 탭으로 여는 클릭(Ctrl·Cmd 등)은 바로 열고 목록에서 읽음 처리한다. 이미 읽은 알림은 바로 이동한다.
- 검증: `npm run check` 통과(Vitest 178개). 중간에 Wi-Fi가 끊겨 PC가 느려진 동안 생활 변화 API 테스트 1개가 시간 초과로 실패했으나, 변경을 뺀 상태에서도 똑같이 실패했고 연결이 돌아온 뒤 통과했다. 브라우저에서 실패 상황은 직접 재현하지 못했다.
