# 관리자 챗봇 근거 문서 관리 화면 (ADM-02~04)

- 작성일: 2026-11-27
- 관련 이슈 / PR: #41(not planned로 닫힘), 선행 #44(공통 클라이언트 FormData, 구현 PR #88·테스트 PR #93)

## 목적

관리자가 API를 직접 부르지 않고 화면에서 챗봇 근거 문서(PDF)를 등록·교체하고 반영 상태를 보게 한다. 업로드는 #44에서 확인한 공통 `apiRequest`의 FormData 지원을 쓴다.

## 핵심 요청

- #44 반영 여부를 #28·#29·#41에서 확인하고, 안 돼 있으면 코드를 바꾼다.
  - #28: 반영돼 있다(고지서 업로드가 `apiRequest`에 FormData를 넘긴다).
  - #29: 다른 사람이 작업 중이라 손대지 않는다(사용자 지시).
  - #41: FE 구현이 없다. 팀원이 not planned로 닫았지만 구현한다(사용자 결정). 이슈 재오픈은 따로 정한다.

## 선택과 이유

| 검토한 방법                                       | 선택 | 이유                                                                                              |
| ------------------------------------------------- | ---- | ------------------------------------------------------------------------------------------------- |
| 문서 상세를 별도 화면(`/admin/documents/:id`)으로 | 제외 | BE에 문서 단건 조회 API가 없다. 주소로 바로 열면 문서 정보를 못 불러온다                          |
| 목록 카드를 펼쳐 관리(정보·버전·업로드·재처리)    | 채택 | 목록 응답에 필요한 정보가 다 있다. 버전은 펼칠 때 `GET .../versions`로 부른다                     |
| 처리 중 상태 갱신: 5초마다 다시 조회              | 채택 | 대기·처리 중인 버전이 있을 때만. 끝나면 멈춘다                                                    |
| 새 버전 업로드의 뺄 쪽: 현재 값을 미리 채움       | 채택 | 현재 버전에 뺀 쪽이 있으면 BE가 값을 꼭 요구한다. 비우면 빈 값으로 보내 "빼지 않음"을 분명히 한다 |
| 재처리: 뺄 쪽이 그대로면 본문 생략                | 채택 | BE가 본문을 생략하면 현재 값을 쓰고, 빈 문자열이면 모든 쪽을 쓴다                                 |

## 반영 내용

- `features/admin/documents.ts`: 타입(`DocumentResponse`·`DocumentVersionResponse`), API 함수, 파일 검사(PDF·30MB), `canRetry`(현재보다 새 실패 버전만), `isProcessing`.
  - 등록·새 버전은 multipart(`FormData`), 정보 수정은 JSON PATCH(보낸 값만), 재처리·다시 반영은 POST.
- `features/admin/use-documents.ts`: TanStack Query 훅. 변경 후 목록·버전 다시 조회. 처리 중이면 5초마다 갱신.
- `features/admin/ui/document-list.tsx`: `/admin/documents` 화면.
  - 새 문서 등록(파일·문서명·원문 링크·발행일·뺄 쪽), 카드(사용 여부·현재/최근 버전·상태·원문 링크).
  - 펼치면: 문서 정보 수정(사용 여부 포함), 버전 목록(상태·실패 단계·이유·조각 수·뺀 쪽, 실패 버전 `다시 반영`), 새 버전 업로드, 현재 버전 재처리.
  - 버전 목록이 카드보다 앞서면(반영이 끝남) 목록을 다시 불러 카드도 맞춘다.
- 관리자 메뉴에 `챗봇 근거 문서`, 라우트 `/admin/documents`(관리자만, 서버도 403).
- 오류 문구: BE `DOCUMENT_*` 오류 10개를 한국어로(관리자 화면은 한국어만).
- MSW: 문서 목록·등록·수정·버전 목록·새 버전·재처리·다시 반영. 조회할 때마다 대기 → 처리 중 → 완료로 넘어가고, 파일 이름이 `fail`로 시작하면 임베딩 단계에서 실패한다. BE처럼 뺄 쪽 필수·진행 중 409·같은 파일 409·형식 오류를 낸다.
