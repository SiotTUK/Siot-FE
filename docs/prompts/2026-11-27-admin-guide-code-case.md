# 관리자 문구 편집기가 코드를 대문자로 바꾸지 않게

- 작성일: 2026-11-27
- 관련 이슈 / PR: https://github.com/SiotTUK/Siot-FE/issues/54

## 목적

관리자 문구 편집기가 입력한 코드를 대문자로 바꿔 조회해서, 소문자 슬러그인 생활수칙 코드(`waste-food` 등)를 열 수 없던 문제(이슈 #54)를 고친다.

## 핵심 요청

요약: 사용자가 이슈 #54를 보자고 했다. AI가 BE 코드를 직접 확인한 뒤, 이번엔 코드 직접 입력을 유지하고 목록에서 고르기는 관리자 생활수칙 화면(#43)에 맡기자고 추천했고 사용자가 그대로 진행하자고 했다.

## 확인한 BE 동작 (BE main `1855de1`)

- `GuideRepository.findByCode`는 대소문자를 구분해 찾는다(`guide.code` VARCHAR, IgnoreCase 없음).
- 생활수칙 코드는 소문자 슬러그다(`V2026_11_26_1610__seed_fe_rules.sql`: `order-noise`, `waste-food` 등).
- `GET /api/admin/rules`(생활수칙 목록)가 있다. 조회 응답에 생활수칙 칸을 더하는 BE PR #28은 merge됐다.

## 선택과 이유

| 검토한 방법                                        | 선택 | 이유                                                                                         |
| -------------------------------------------------- | ---- | -------------------------------------------------------------------------------------------- |
| 대문자 변환만 빼고 직접 입력 유지                  | 채택 | 버그만 고치는 작은 변경. 체크리스트·생활 변화 코드는 원래 대문자라 영향 없음(사용자 결정)    |
| 생활수칙을 목록(`GET /api/admin/rules`)에서 고르기 | 제외 | 목록 API 연결과 고르는 화면이 필요해 관리자 생활수칙 화면(#43)과 겹친다. #43에서 함께 만든다 |

## 반영

- `src/features/admin/ui/guide-editor.tsx`: `code.trim().toUpperCase()` → `code.trim()`. 낡은 주석("항목 목록 API가 아직 없다")을 지금 상황(대소문자 구분, 생활수칙 목록은 #43)으로 고치고, 입력칸 예시를 `CL-01 · waste-food`로 바꿨다.
- `src/mocks/handlers/admin.ts`: 관리자 문구 조회·저장이 생활수칙 코드(FE `ruleEntries` 17개)도 받는다. BE처럼 대소문자를 구분하고, 저장한 적 없는 생활수칙은 FE 내용(제목·요약)으로 만든 4개 언어 문구를 돌려준다(BE는 4개 언어를 시드로 넣어 둔다).
- `src/features/admin/api.test.ts`: `waste-food`는 열리고 `WASTE-FOOD`는 404 `GUIDE_NOT_FOUND`인 계약 테스트.

## 검증

- `npm run check` 통과(Vitest 193개).
- 390×844 목업 관리자 화면: `waste-food` → 제목 "음식물 쓰레기"·요약이 채워짐, `WASTE-FOOD` → "항목을 찾을 수 없어요", `CL-01` → 기존처럼 "외국인등록".
- 실제 서버: 확인하지 못했다. 사용자 계정이 관리자(`ADMIN`)가 아니라 관리자 API를 부를 수 없다.
- 참고: 편집기 화면 제목은 아직 "체크리스트 문구"다. 생활수칙까지 다루는 이름으로 바꿀지는 #43에서 정한다.
