# 로그인·탈퇴 비밀번호 검증을 BE 요청 검증에 맞춤

- 작성일: 2026-11-27
- 관련 이슈 / PR: https://github.com/SiotTUK/Siot-FE/issues/55

## 목적

로그인·탈퇴 폼은 비밀번호가 비어 있는지만 봐서, 공백만 있거나 64자를 넘는 비밀번호(로그인은 255자 넘는 이메일도)를 보내면 BE가 요청 검증에서 막고 일반 `INVALID_INPUT`("입력한 내용을 다시 확인해 주세요")이 나왔다(이슈 #55).

## 핵심 요청

요약: 사용자가 이슈 #55를 보자고 했다. AI가 BE 코드를 직접 확인한 뒤, 64자·255자 초과를 FE에서 막고 로그인 실패·비밀번호 불일치와 같은 문구를 보여 주는 방법을 추천했고 사용자가 그대로 진행하자고 했다.

## 확인한 BE 동작 (BE main `87b6c5a`)

- `LoginRequest`: email `@NotBlank @Size(max = 255)`, password `@NotBlank @Size(max = 64)`.
- `WithdrawalRequest`: password `@NotBlank @Size(max = 64)`.
- 이 검증에 걸리면 `AuthService`(LOGIN_FAILED·실패 횟수)나 `MemberWithdrawalService`(PASSWORD_INCORRECT)까지 가지 않는다.

## 선택과 이유

| 검토한 방법                                                           | 선택 | 이유                                                                                                                             |
| --------------------------------------------------------------------- | ---- | -------------------------------------------------------------------------------------------------------------------------------- |
| FE에서 BE와 같은 기준으로 막고, 맞을 수 없는 값은 실패 문구로         | 채택 | 가입 비밀번호는 8~64자·공백 없음이라 64자 초과는 맞는 비밀번호일 수 없고, 255자 초과 이메일도 가입된 계정일 수 없다(사용자 결정) |
| 서버 `INVALID_INPUT`을 로그인 실패·비밀번호 불일치 문구로 바꿔 보이기 | 제외 | 다른 이유의 입력 오류까지 같은 문구로 덮인다                                                                                     |

## 반영

- `src/features/auth/credential-schemas.ts`(새 파일): 로그인·탈퇴 스키마.
  - 비밀번호가 비었거나 공백만 있으면 `validation.passwordRequired`.
  - 64자 초과: 로그인은 `errors.LOGIN_FAILED`, 탈퇴는 `errors.PASSWORD_INCORRECT`. 서버가 실패 횟수를 세지 않으므로 "(2/5)"는 붙지 않는다.
  - 로그인 이메일 255자 초과(앞뒤 공백 제거 후)는 `errors.LOGIN_FAILED`.
  - 비밀번호는 입력한 그대로 보낸다(앞뒤 공백도 자르지 않음).
- `login-form.tsx`·`withdrawal-form.tsx`: 새 스키마를 쓰고, 실제와 달랐던 주석("무엇이 틀리든 서버가 LOGIN_FAILED")을 고쳤다.

## 검증

- `npm run check` 통과(Vitest 192개, 스키마 테스트 10개 추가: 빈 값·공백만·64자 허용·65자·256자 이메일).
- 390×844 목업 화면: 로그인에서 공백만 → "비밀번호를 입력해 주세요", 65자 → "이메일 또는 비밀번호가 맞지 않아요", 256자 이메일 → 같은 실패 문구, 세 경우 모두 로그인 요청을 보내지 않음. 정상 로그인은 홈으로 이동. 탈퇴에서 공백만 → "비밀번호를 입력해 주세요", 65자 → "비밀번호가 맞지 않아요", 확인 단계로 넘어가지 않고 요청도 보내지 않음.
- 실제 BE로는 확인하지 않았다(실제 계정으로 로그인·탈퇴 실패를 일부러 만들지 않음).
- 스크린샷(목업, 390×844), 리뷰 반영 전: [로그인 65자](assets/2026-11-27-auth-password-login.png), [탈퇴 65자](assets/2026-11-27-auth-password-withdrawal.png)

## 2026-11-27 후속: PR #61 셀프 리뷰 반영

- 요약: 사용자가 PR #61 리뷰를 요청했다. 막을 문제는 없었고 사소한 두 가지를 짚었다. 로그인 폼은 칸을 벗어날 때 검사해서(`mode: 'onTouched'`) 65자 비밀번호·256자 이메일을 입력하고 다른 칸을 누르기만 해도 "이메일 또는 비밀번호가 맞지 않아요"가 떴고, 두 폼에 이름만 바꾸는 `schema` 별칭이 있었다. 사용자가 둘 다 고치자고 했다.
- 반영: 로그인 폼에서 `errors.LOGIN_FAILED` 문구는 로그인 버튼을 누른 뒤(`isSubmitted`)에만 보이게 했다. "비밀번호를 입력해 주세요"는 전처럼 칸을 벗어나면 보인다. 별칭을 지우고 `loginSchema`·`withdrawalSchema`를 바로 쓴다.
- 검증: `npm run check` 통과(Vitest 192개). 목업 로그인에서 빈 비밀번호 + 칸 벗어남 → "비밀번호를 입력해 주세요", 65자 + 칸 벗어남 → 문구 없음, 로그인 버튼 → "이메일 또는 비밀번호가 맞지 않아요", 다시 바르게 입력 → 문구 사라짐.

## 2026-11-27 후속: 실제 서버 확인에서 찾은 문제

- 요약: 사용자가 실제 서버로 확인해 달라고 했다. AI가 5173(실제 BE 프록시)에서 로그인 화면을 확인하다가, 서버 로그인 실패 "(1/5)"를 받은 뒤 256자 이메일로 다시 누르면 FE에서 막혀 서버로 가지 않았는데도 지난 "(1/5)" 안내가 비밀번호 칸에 남아 새 문구와 함께 보이는 것을 찾았다. 이 PR 전에는 다시 누를 때마다 서버로 가서 안내가 새로 바뀌었기 때문에 드러나지 않았다. 사용자가 고치자고 했다.
- 반영: FE 검사에서 막히면(`handleSubmit` 실패 콜백) 지난 서버 오류를 지운다(`submit.reset()`).
- 검증: `npm run check` 통과(Vitest 192개). 실제 서버에서 가짜 주소(`check@example.com`)로 로그인 실패 "(1/5)" → 256자 이메일로 다시 누름 → 이메일 칸 문구 하나만 남고 "(1/5)"는 사라짐 → 65자 비밀번호도 같은 문구 하나. 서버 요청은 첫 실패 한 번뿐. 공백만 있는 비밀번호, 65자 칸 벗어남(문구 없음)·제출(문구, 요청 없음)도 실제 서버 화면에서 확인. 이어서 사용자가 로그인한 뒤 실제 서버 탈퇴 화면에서 공백만 → "비밀번호를 입력해 주세요", 65자 → "비밀번호가 맞지 않아요"를 확인했다. 두 경우 모두 확인 단계로 넘어가지 않고 요청도 나가지 않았다(최종 탈퇴 버튼은 누르지 않음).
