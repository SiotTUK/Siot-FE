# 체크리스트 '번역 준비 중'과 세금 상세 (BE #29·#30 반영)

- 작성일: 2026-11-27
- 관련 이슈 / PR: FE 전용 이슈 없음(관련 #34·#50) / PR 미생성

## 목적

BE main에 반영된 응답 필드를 FE에 연결한다.

- 체크리스트 `contentLanguage`·`translated`
- 세금 상세 `contact`
- 일정 `taxScheduleId`
- 생활 수칙 세금 항목의 `taxKind`와 `GET /api/schedules/taxes?kind=`

## 선택과 이유

| 검토한 방법                              | 선택                                              | 이유                                                                                                                         |
| ---------------------------------------- | ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| '번역 준비 중'을 본문 글자로 판단        | 제외                                              | 안내대로 `translated === false`만 본다. 필드가 없는 예전 응답은 표시하지 않는다                                              |
| 세금 상세를 `/api/schedules/{id}`로 열기 | 제외                                              | 안내대로 항상 `/api/schedules/taxes/{id}`로 연다                                                                             |
| 생활 수칙 `taxKind`를 API 응답에서 읽기  | 보류 → 채택(아래 추가 기록)                       | 처음에는 FE 매핑을 두었다가, 요청에 따라 `GET /api/rules/{code}`의 `taxKind`로 바꿨다                                        |
| 생활 수칙에서 열 세금 회차               | 마감이 지나지 않은 첫 회차, 없으면 가장 최근 회차 | BE 제안(지나지 않은 첫 회차)을 따른다. 회차 목록 화면이 없어 "없으면 목록" 대신 가장 최근 회차를 연다. BE 확인 요청 항목이다 |
| `taxScheduleId`·`?kind=`가 비었을 때     | 링크 숨김                                         | 안내대로. 개인 일정은 `scheduleId`가 null이라 `taxScheduleId`만 본다                                                         |

## 반영 내용

- 체크리스트: `contentLanguage`·`translated` 타입과 `translationPending`. 홈·생활 변화 할 일 줄과 체크리스트 상세에 '번역 준비 중'(4개 언어). 경고·기한 표시는 그대로다.
- 세금 상세 화면 `/calendar/taxes/:scheduleId`(CAL-03):
  - 제목·D-day(서버 `dDay`)·요약
  - 납부 기간·대상·내는 곳·준비물·세율·가산세·근거 법령(쪽수)·문의
  - 본문, 납부 링크
  - 값이 없는 행과 `contact`가 null이면 숨긴다. 404는 "세금 안내를 찾을 수 없어요"다.
- 생활 달력: 일정에 `taxScheduleId`가 있으면 "세금 상세 보기 ›".
- 생활 수칙 상세: 세금 항목이면 `?kind=` 목록에서 회차를 골라 "세금 상세 보기" 카드. 비거나 실패하면 숨긴다.
- 목업:
  - 체크리스트 `contentLanguage: 'ko'`, 한국어 회원만 `translated: true`(BE 시드와 같다)
  - 주민세 공통 일정에 `taxScheduleId`
  - `GET /api/schedules/taxes/{id}`·`?kind=` 핸들러. 주민세만 있고 다른 종류는 빈 목록이다
- 정리: #85 병합 때 남은 중복 라우트 `/home/life-changes`(뒤 줄은 쓰이지 않음)를 지웠다.
- 공통 코드 영향: 없음. 라우터에 경로 하나를 추가했다.

## 2026-11-27 추가: `taxKind`를 BE 응답에서 읽음

- 요청: 생활 수칙 세금 종류는 BE에 이미 있으니 최근 BE 커밋을 확인해 교체한다. 회차는 마감이 지나지 않은 첫 회차, 모두 지났으면 가장 최근 회차를 연다.
- 확인: BE `240c25e`(#29)에서 `RuleResponse.taxKind`가 추가됐다(`GET /api/rules/{code}`).

| 검토한 방법                      | 선택 | 이유                                                                                         |
| -------------------------------- | ---- | -------------------------------------------------------------------------------------------- |
| FE 코드 매핑(`ruleTaxKind`) 유지 | 제외 | 사용자 요청. BE가 정한 값을 그대로 쓴다                                                      |
| 생활 수칙 화면 전체를 API로 전환 | 제외 | #42 범위다. 이번에는 `GET /api/rules/{code}`에서 `taxKind`만 읽는다(`features/rules/api.ts`) |
| 회차 선택                        | 유지 | 이미 요청과 같다(`pickTaxRound`: `dDay ≥ 0`인 첫 회차, 없으면 마지막 회차)                   |

반영 내용

- `features/rules/api.ts`: `fetchRule`·`useRuleTaxKind`. 응답에서 `code`·`taxKind`만 타입으로 둔다.
- `TaxDetailLink`는 `taxKind`를 받는다. 값이 없거나(null·로딩·오류·없는 코드) 회차 목록이 비면 숨긴다.
- `taxes.ts`의 FE 매핑과 테스트를 지웠다.
- 목업: `GET /api/rules/:code`. BE 시드와 같은 `taxKind`이고, 없는 코드는 404다.
