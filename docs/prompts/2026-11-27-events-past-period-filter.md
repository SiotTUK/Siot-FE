# 행사 목록 지난 행사 보기·기간 필터

- 작성일: 2026-11-27
- 관련 이슈 / PR: #53 / [PR #58](https://github.com/SiotTUK/Siot-FE/pull/58)

## 목적

BE `GET /api/events`는 EVE-10 조건으로 `past`·`from`·`to`를 지원하지만 FE는 `page`만 보내 지난 행사를 찾거나 기간으로 좁힐 수 없었다. 이 두 조건을 목록 화면에 연결한다. 지역·정렬(#33)과 카테고리(#37)는 범위에서 제외한다.

## 핵심 요청

- 이슈 #53의 할 일 해결 요청. 범위는 이슈 본문을 따른다.

## 선택과 이유

| 검토한 방법                                          | 선택 | 이유                                                                                                |
| ---------------------------------------------------- | ---- | --------------------------------------------------------------------------------------------------- |
| 필터 값을 URL 검색어(`past`·`from`·`to`)로 유지      | 채택 | 이슈 요구. 새로고침·상세에서 돌아오기 시 유지되고, 상세 뒤로가기 경로가 이미 `/events?…`를 허용한다 |
| `from > to`면 요청을 보내지 않고 입력 아래 오류 표시 | 채택 | 서버 400을 미리 막는다. 서버 400 `INVALID_INPUT`도 별도 문구로 처리해 FE 검증에만 의존하지 않는다   |
| 필터 변경 시 페이지를 처음으로, 다른 검색어는 유지   | 채택 | 이후 #33·#37의 `region`·`category` 검색어와 함께 쓸 수 있게 한다                                    |

## 반영 내용

- `src/features/events/event-filters.ts`: URL 파싱·날짜 형식 검증·기간 검증·API 쿼리 문자열 생성
- `fetchEvents`·`useEvents`·`eventKeys.list`에 필터 추가. 기간이 잘못되면 쿼리를 실행하지 않는다
- `EventListFilters` 컴포넌트: `진행 중·예정`/`지난 행사` 칩, 시작일·종료일, `필터 초기화`. #33·#37 필터를 같은 영역에 붙일 수 있게 둔다
- 목록 화면: 페이지 이동 시 필터 유지(기존에는 검색어를 모두 지웠다), 빈 상태 문구를 지난 행사·기간 필터별로 구분, 서버 400 처리
- 4개 언어 문구 추가
- MSW: 지난 행사 샘플 2건, `past`·기간 겹침 필터, 정렬, `from > to`·날짜 형식 400

## 2026-11-27 후속 작업

- 행사 상태를 `진행중`, `예정`, `종료`로 분리한다. 초기 선택은 `진행중`이며 상태 변경 시 선택 기간을 유지하고 첫 페이지로 돌아간다. 기존 `past=true` 주소는 `종료`로 연다.
- 한국 날짜 기준으로 오늘 시작하거나 종료하는 행사는 `진행중`에 포함한다. 기간 조건은 기존처럼 행사와 하루 이상 겹치는지 확인한다. 진행 중인 행사가 미래 날짜까지 이어지면 그 기간으로도 찾을 수 있다.
- 기존 BE 조회 조건과 날짜순 정렬을 이용해 두 상태의 경계를 찾고, 상태별 결과 수와 페이지를 계산한다.
- 최신 `main` 병합에서 행사 목록 쿼리 키의 충돌을 해결했다. 필터별 캐시를 유지하면서 행사 구독이 목록 전체를 다시 조회하도록 기존 접두사를 보존했다.
- `npm run check`에서 타입·린트·서식·Vitest 227개·빌드를 통과했다. 실제 BE 연동은 검증하지 않았다.

Chrome 390×844 목업에서 세 상태별 결과, 미래 기간과 겹치는 진행 중 행사, 기간 오류, 새로고침 후 선택 유지, 초기화, 4개 언어 표시를 확인했다.
