# 새로고침하면 언어가 한국어로 판단되는 문제 수정

- 작성일: 2026-11-27
- 관련 이슈 / PR: #84

## 목적

영어로 바꾼 뒤 새로고침하면 화면 문구는 영어인데 위쪽 언어 선택이 "한국어"로 보이고, 체크리스트를 한국어(`language=ko`)로 요청하는 문제를 고친다.

## 핵심 요청

- 요약: 사용자가 영어로 바꿨는데 홈에 한국어가 보인다고 했다. AI가 확인해 원인 두 가지(앱의 언어 판단 버그, 서버에 기본 체크리스트 항목의 영어 제목이 없음)를 설명했고, 사용자가 언어 버그는 별도 fix 브랜치에서 고치고 서버 번역은 지금 두기로 했다.

## 선택과 이유

| 검토한 방법                                                       | 선택 | 이유                                                      |
| ----------------------------------------------------------------- | ---- | --------------------------------------------------------- |
| `currentLanguage()`가 `resolvedLanguage`가 비면 `language`를 씀   | 채택 | 한 곳만 고치면 언어 선택·요청 언어가 모두 맞는다          |
| i18n 초기화 뒤 `changeLanguage`를 한 번 더 호출                   | 제외 | 시작 순서에 기대는 방법이라 같은 문제가 다시 생기기 쉽다  |
| 관리자 화면에서 기본 체크리스트 항목을 다시 저장해 자동 번역 생성 | 보류 | 실제 서버 데이터 변경이라 지금은 두기로 했다(사용자 결정) |

## 반영 내용

- 원인: 메시지 묶음을 `init` 뒤에 추가하기 때문에 i18next의 `resolvedLanguage`가 시작 직후 비어 있다(언어를 한 번 바꿔야 채워진다). `currentLanguage()`는 비어 있으면 `ko`를 돌려줘서 언어 선택이 "한국어"로 보이고, 이 값을 쓰는 요청(체크리스트 등)이 한국어로 나갔다. 화면 문구는 `language`(영어)로 나와서 둘이 어긋났다.
- `src/shared/i18n/index.ts`: `resolvedLanguage`가 비면 `language`를 쓰고, 지원하지 않는 언어면 `ko`.
- `src/shared/i18n/index.test.ts`: 시작 직후 상태(`resolvedLanguage` 없음, `language=en`)에서 `en`을 돌려주는지, 지원하지 않는 언어는 `ko`인지.

## 2026-11-27 후속: 리뷰 반영

- 요약: 사용자가 #84 리뷰를 요청했다. AI는 막는 문제는 없다고 보고, 사소한 제안 두 가지(언어 판단 기준을 하나로 맞추기, 기록의 PR 번호)를 냈다. 사용자가 둘 다 고치기로 했다.
- 반영
  - `currentLanguage()`가 `language`(`t()`가 쓰는 언어)를 먼저 보고, 지원하지 않는 값일 때만 `resolvedLanguage`, 그다음 `ko`를 쓴다. 생활 수칙의 `useScreenLanguage()`가 같은 이유(`resolvedLanguage`가 바꾼 직후 이전 언어로 남을 수 있음)로 `language`를 따로 읽던 것을 `currentLanguage()`로 합쳤다.
  - 테스트: `resolvedLanguage`가 이전 언어(`ko`)로 남아 있어도 `language`(`vi`)를 돌려주는지 추가.
  - 이 기록의 "관련 이슈 / PR"을 #84로 바꿨다.

## 남은 작업

- 실제 서버의 기본 체크리스트 항목(CL)은 한국어 문구만 있어 영어로 요청해도 한국어 제목이 온다. 관리자 화면에서 한국어를 다시 저장하면 자동 번역이 생기고, 오래 남기려면 백엔드 초기 데이터에 넣어야 한다.
