# 목업 값을 실제 BE 응답에 맞춤

- 작성일: 2026-11-27
- 관련 이슈 / PR: https://github.com/SiotTUK/Siot-FE/issues/56

## 목적

MSW 목업이 실제 BE가 보내지 않는 값을 줘서 목업 화면이 실제 화면과 달라지는 문제(이슈 #56)를 고친다.

## 핵심 요청

요약: 사용자가 이슈 #56을 보자고 했고, AI가 이슈 내용만 옮기자 백엔드도 확인했는지 물었다. 백엔드 코드와 실제 서버 응답을 확인한 뒤, 공통 일정은 세금 일정으로 바꾸기로 사용자가 정했다.

## 확인한 BE 동작 (BE main `87b6c5a`, 실제 서버)

- 체크리스트: `ChecklistService`는 기한이 있을 때만 `dDay`·`dDayText`("기한 지남"·"D-Day"·"D-n")를 채우고, 기한이 없으면 둘 다 `null`이다. 실제 서버도 기한 없는 항목(CL-04·CL-07·CL-12)을 `null`로 보낸다.
- 일정: BE 코드가 만드는 `kind`는 `STAY_EXPIRY`·`STAY_EXTENSION_START`·`TAX_CAR`·`TAX_PROPERTY`이고, 공통 일정은 관리자가 DB에 넣은 값이다. `LIFE`를 만드는 곳은 없다. BE 시드에는 공통 일정이 없고, 실제 서버 2026-11~2027-07 중 다섯 달을 조회했을 때도 세금·체류 일정만 있었다.

## 선택과 이유

| 검토한 방법                           | 선택 | 이유                                                                                           |
| ------------------------------------- | ---- | ---------------------------------------------------------------------------------------------- |
| 공통 일정을 세금 일정(`TAX`)으로      | 채택 | 실제로 보이는 일정과 같은 모양이고, 목업에서 공통 일정 화면을 계속 확인할 수 있다(사용자 결정) |
| 공통 일정을 목업에서 빼기             | 제외 | 실제와 더 같지만 목업에서 공통 일정 화면을 확인할 수 없다                                      |
| 기한 없는 항목의 문구를 FE에서 만들기 | 제외 | BE가 주지 않는 값이고 이슈 범위 밖이다                                                         |

## 반영

- `src/mocks/handlers/checklist.ts`: 기한 없는 항목(CL-04·CL-06~09)의 `dDayText`를 없앴다. `dDay`·`dDayText`는 기한이 있을 때만 계산된다.
- `src/mocks/handlers/schedules.ts`: 공통 일정을 `kind: 'TAX'`, "주민세(개인분) 납부"(4개 언어)로 바꿨다.

## 검증

- `npm run check` 통과(Vitest 182개). 이 목업 값에 기대는 테스트는 없었다.
- 390×844 목업 화면: 홈 체크리스트에서 기한 없는 카드(건강보험 가입 확인·직장을 바꿀 때 절차)에 기한 문구가 없고 레이아웃이 어색하지 않음. 생활 달력에 "주민세(개인분) 납부"가 보이고 영어·중국어·베트남어 제목도 확인.
- 목업 기준으로 저장소에 둔 스크린샷 중 바뀐 값이 찍힌 것은 없었다.
