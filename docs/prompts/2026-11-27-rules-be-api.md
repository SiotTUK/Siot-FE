# 생활 수칙 화면을 BE API로 전환

- 작성일: 2026-11-27
- 관련 이슈 / PR: #42, PR 미생성. 선행: SiotTUK/Siot-BE#14(데이터 이전), SiotTUK/Siot-BE@e05365f(#73 항목 추가)

## 목적

생활 수칙 화면(M06 목록·분야·FAQ, 상세)이 FE 정적 데이터(`content.ts`) 대신 BE 생활수칙 API를 읽게 한다. BE가 데이터의 기준이 되어, 관리자 수정·새 항목(#73)이 배포 없이 화면에 반영된다.

## 핵심 요청

요약: 사용자가 #42를 가져와 처리하라고 했다. 화면 구성은 이슈대로 유지하고 데이터 출처만 바꾼다.

## 선택과 이유

| 검토한 방법                                        | 선택 | 이유                                                                                                                                                                                              |
| -------------------------------------------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `content.ts`를 지우지 않고 `src/mocks/data`로 옮김 | 채택 | 운영 코드는 목업 데이터를 참조하지 않되(작업 지침), `npm run dev:mock`·관리자 목업이 BE와 같은 문구를 계속 보여 주게 한다(AI 판단). 운영 번들에서 1,100줄 문구가 빠진다                           |
| 분류 칩·타일은 FE 고정 목록(`ruleCategories`) 유지 | 채택 | 이름·주제·설명·아이콘이 시안 문구라 API의 카테고리 이름으로 바꾸지 않았다. 규칙의 `categoryKey`로 분류만 맞춘다. 관리자가 새로 만든 분류(키 없음)는 검색·상세에만 보인다(AI 판단)                 |
| 검색은 받은 목록에서 FE가 거름                     | 채택 | 목록 API에 검색 파라미터가 없다(이슈 계획대로)                                                                                                                                                    |
| "과태료 있음" 태그를 요청 언어 문구로 판정         | 채택 | API는 한 언어만 준다. 언어별 낱말(과태료·범칙금 / fine / 罚款 / phạt)로 판정하고, 기존 18개 항목에서 4개 언어 모두 한국어 판정과 같음을 확인했다. 번역이 없으면(`translated=false`) 한국어로 판정 |
| 범칙금(#73 공공예절)도 같은 태그로 표시            | 보류 | 지금은 "과태료 있음"이 붙는다. 범칙금은 과태료와 다른 제도라 태그 문구를 바꿀지 담당자 확인이 필요하다                                                                                            |
| 알림 링크의 규칙 코드 검사를 슬러그 모양 검사로    | 채택 | 코드 목록이 BE에 있다. 모양이 맞으면 상세로 보내고, 없는 코드는 상세가 "찾을 수 없어요"로 답한다. 예전 코드(`RUL-03`)는 그대로 목록으로                                                           |

## 반영 내용

- `features/rules/api.ts`: `RuleResponse`·`RuleFaqResponse` 타입(화면이 읽는 필드), `GET /api/rules`·`/api/rules/faq`·`/api/rules/{code}` 요청과 TanStack Query 훅. 언어가 쿼리 키에 있어 언어를 바꾸면 다시 조회한다. 404 `GUIDE_NOT_FOUND` 판별(`isRuleNotFound`).
- `rules.ts`: `toRule`(BE 필드 → 화면 정보: `when`·`place`→장소·`fee`·`penalty`·`law`·`contact`, 확인일 `checkedOn`, `translated`, `taxKind`), `toFaqItems`(지운 항목을 가리키는 FAQ는 뺌), `mentionsFine`. 정적 타입(`RuleEntry`·`Localized`)과 `localizeRule`을 지웠다.
- 화면: 목록 검색 결과·FAQ, 분야 목록, FAQ 전체, 상세를 `QueryState`(로딩 → 실패와 다시 시도 → 내용)로 감쌌다. 상세는 없는 코드면 "이 안내를 찾을 수 없어요". 확인일은 항목별 `checkedOn`. 세금 상세 링크는 응답의 `taxKind`를 바로 쓴다(별도 요청 없음).
- "번역 준비 중"(`translated=false`) 태그를 카드·상세에 추가(4개 언어, 체크리스트와 같은 문구).
- 아이콘이 없는 새 항목(#73)은 분류 아이콘으로 표시한다.
- MSW: `GET /api/rules`(분류 필터), `/api/rules/faq`, `/api/rules/{code}`를 BE 응답 형태로 제공하고 잘못된 `language`는 400으로 답한다. 목업 데이터 검사(4개 언어·https 출처·FAQ·연락처·과태료 판정 일관성)는 `src/mocks/data/rule-content.test.ts`로 옮겼다.
- 오류 신고(`정보 오류 신고`)는 이미 규칙 코드로 보내고 있어 바꾸지 않았다.
