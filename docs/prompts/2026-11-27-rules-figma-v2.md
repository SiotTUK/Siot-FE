# 생활 수칙 화면을 Figma v2에 맞춤

- 작성일: 2026-11-27
- 관련 이슈 / PR: 미생성. 관련 #42(생활 수칙 BE API 전환)

## 목적

Figma "생활 달력과 생활 수칙"의 M06 생활 수칙 화면에 맞춰 생활 수칙 목록 화면의 디자인을 바꾼다. 상세 화면(M07)은 바꾸지 않는다.

## 핵심 요청

요약: 시작·회원가입, 온보딩에 이어 사용자가 생활 수칙 디자인도 Figma를 참고해 바꿔 달라고 했다. AI가 세 가지를 물었고 사용자가 모두 추천안을 골랐다.

## 선택과 이유

| 검토한 방법                          | 선택 | 이유                                                                                              |
| ------------------------------------ | ---- | ------------------------------------------------------------------------------------------------- |
| 분야 타일을 누르면 그 분야 목록 화면 | 채택 | 기존 분야 필터(`?category=`)를 그대로 쓰고, 브라우저 뒤로가기로 돌아온다(사용자 결정)             |
| 타일 아래에 바로 펼치기              | 제외 |                                                                                                   |
| "최근 바뀐 안내" 칸 빼기             | 채택 | FE 고정 내용이라 바뀐 날짜가 없다. 가짜 날짜를 보여 주지 않고 #42(BE 전환) 때 넣는다(사용자 결정) |
| FAQ는 번호 목록, 누르면 상세로       | 채택 | Figma대로(사용자 결정). 모아 볼 화면이 없어 "전체 ›"는 넣지 않았다                                |

## 반영

- 제목 아래 설명 "시흥에서 지켜야 할 규칙과 생활 정보를 모았어요", 검색칸 예시 "(예: 음식물 쓰레기)"(4개 언어).
- 분야 칩과 분야별 펼침 카드 대신 "분야별 안내" 3×2 타일(`RuleCategoryGrid`): 분야마다 색이 다른 아이콘 상자, 이름, 주제. 아이콘을 Figma 모양(사람·휴지통·자동차·원 동전·버스·책)으로 바꿨다. 주제 글은 Figma 예시 문구 대신 실제 내용에 맞는 기존 문구를 쓴다(Figma 예시의 "예절·신호·시흥패스+"는 내용에 없다).
- 타일을 누르면 `?category=` 화면: "‹ 전체 분야" 링크와 그 분야 카드(아이콘·이름·주제 + 수칙 목록).
- "자주 묻는 질문 TOP 5": 한 카드 안 번호 목록(1~3은 브랜드 색), 누르면 해당 수칙 상세.
- 맨 아래 토로 안내 "찾는 수칙이 없으면 질문 탭에서 토로에게 물어봐요"(4개 언어).
- 쓰지 않게 된 문구(`rules.categoriesLabel`·`all`·`viewAll`·`more`)와 CSS(▼ 표시, 펼침 카드, FAQ 펼침)를 지웠다.

## 2026-11-27 후속: Figma에 새로 생긴 분야·상세 화면

- 요약: 사용자가 Figma에서 생활 수칙 관련 변경을 확인해 달라고 했다. AI가 다시 읽어 보니 M06은 그대로이고 "생활 수칙 · 분야"·"생활 수칙 · 상세" 화면이 새로 생겼다. 백엔드(main `1855de1`)로 받을 수 없는 칸(분야 설명, 수칙별 아이콘·대상 태그, 단계 제목/설명, 낮/밤 같은 수칙별 정보, 문의처 번호 분리)을 정리했고, 사용자가 생활 수칙은 원래 FE 내용이라는 점을 확인한 뒤 "FE 내용 유지"로 두 화면을 만들자고 했다.
- 원칙: 새 사실을 지어내지 않는다. 화면은 FE 내용에 이미 있는 값으로만 채운다.
- 분야 화면(`/rules/category/:category`): ‹ 분야 이름 헤더, 분야 칩(공용 `ChipGroup`에 `variant="pill"` 추가, 한 줄 가로 스크롤), 분야 카드(아이콘·이름·설명), "수칙 N개", 수칙 카드(`RuleCard`: 수칙별 아이콘, 제목, 요약 두 줄, 태그), 토로 안내. 첫 화면 타일이 이 화면을 열고, 예전 `/rules?category=` 주소도 이리로 보낸다.
  - 분야 설명 한 줄은 UI 문구로 4개 언어를 새로 썼다(`rules.descriptions.*`, 각 분야 내용을 요약한 안내문).
  - 수칙별 아이콘은 FE 코드(`RuleIcon`)에 수칙 코드별로 정했다(스피커·금연·휴지통·음식·재활용·소파·P·종·신분증·집·자동차·카드·지갑·자전거·전화·건물·가족·가방).
  - 태그는 내용에서 나오는 것만: 불이익에 "과태료"가 있으면 "과태료 있음". Figma 예시의 "공동주택"·"상담 기관" 같은 대상 태그는 내용에 없어 넣지 않았다.
- 상세 화면: 헤더 ‹ 수칙 제목 · 공유(브라우저 공유, 없으면 링크 복사), 분야·과태료 태그, 제목·요약, "이렇게 하세요"(기존 확인 문장을 번호 목록으로), "알아 두세요"(언제·어디서·비용·불이익 카드), 문의처 카드와 전화 걸기(문의 글에서 번호를 뽑는 `parseContacts`, 여러 곳이면 카드도 여러 개), 근거 법령·출처 N개(누르면 출처 링크), 화면 아래 고정 버튼 "정보 오류 신고"·"토로에게 질문하기".
  - Figma의 단계별 제목/설명, 낮/밤 시간 카드, 소음 종류 설명처럼 내용에 구조가 없는 칸은 만들지 않았다(확인 문장 목록이 그 내용을 담는다).
  - 정보 오류 신고는 백엔드 `POST /api/reports`에 `guideCode`(수칙 코드)로 보낸다(`rule-report.ts`, 행사 신고와 같은 흐름·로그인 세션 묶기). 목업도 수칙 코드 신고를 받는다.
  - 토로에게 질문하기는 질문 화면(`/chat`)을 연다. 질문 내용을 미리 채우지는 않는다(챗봇은 지금 행사 질문만 미리 채울 수 있다).
- 정리: 쓰지 않게 된 `RuleCategoryCard`, `rules.allCategories`, 예전 상세 CSS(파란 제목 카드·목록·사실 표)를 지웠다.
- 검증: `npm run check` 통과(Vitest 233개, 추가: 모든 수칙 문의처의 4개 언어 번호 추출, 문의 글 분해, 과태료 태그, 수칙 신고 계약 3개). 목업에서 타일 → 분야 화면, 칩으로 분야 바꾸기, 분야 → 상세 → ‹ 로 분야 화면, 전화 걸기 링크 `tel:16612642`, 정보 오류 신고 접수, 예전 `/rules?category=tax` → `/rules/category/tax`, 영어 화면을 확인했다.
