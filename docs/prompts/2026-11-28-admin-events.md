# 관리자 행사 관리 화면 (ADM-05·EVE-07~09)

- 작성일: 2026-11-28
- 관련 이슈 / PR: SiotTUK/Siot-FE#40

## 목적

공공 API로 수집되지 않는 행사를 관리자가 직접 등록하고, 번역·내용 오류를 고치거나 지우고, 수집을 바로 실행할 수 있게 한다. BE `AdminEventController` 계약을 그대로 쓴다(BE 변경 없음).

## 핵심 요청

- 이슈 #40을 진행한다. 관리자 화면 문구는 한국어만 둔다(이슈에 명시).
- 이슈의 "오류 신고 처리(ADM-07) 화면에서 해당 행사로 이동"은 ADM-07 화면(#39, 열림)이 아직 없어 이번에는 행사 상세 경로 `/admin/events/:eventId`만 만들고 연결은 #39에서 한다(AI 판단, 사용자 확인 전).

## 선택과 이유

| 검토한 방법                | 선택                                                                                  | 이유                                                                                            |
| -------------------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 수정 요청                  | 불러온 값과 비교해 바뀐 칸만 보냄(AI 제안)                                            | BE는 보낸 칸을 모두 잠근다(`lockedFields`). 통째로 보내면 모든 칸이 잠겨 수집이 갱신하지 못한다 |
| 날짜·시각·신청 마감 비우기 | 수정 폼에서 막음(AI 제안)                                                             | BE는 이 칸의 `null`을 "그대로"로 읽어 비울 수 없다. 글 칸은 `""`로 비운다                       |
| 신청 마감 입력             | `datetime-local`을 한국 시간으로, `+09:00` 붙여 보냄(AI 제안)                         | 서버는 `OffsetDateTime`. 관리자 PC 시간대와 상관없이 한국 시간으로 맞춘다                       |
| 중복 행사                  | 409 `details.eventIds`를 링크로 보이고 "그래도 등록" 확인 후 `force=true`(이슈 요구)  | 같은 행사인지 열어 보고 판단하게 한다                                                           |
| 일정 변경 알림             | 날짜·시각을 바꾸면 폼에 안내(AI 제안)                                                 | BE가 알림 신청 회원에게 일정 변경 알림(NTF-02)을 보낸다. 생활수칙처럼 선택지는 없다             |
| 삭제한 행사                | 읽기 전용(AI 판단)                                                                    | BE는 수정을 허용하지만 회원에게 보이지 않고 되살릴 수 없어, 생활수칙 화면과 같게 막았다         |
| 수집 바로 실행             | 목록 위 버튼, 마지막 수집 시각(`/api/events/collection-status`), 출처별 결과(AI 제안) | 이슈 요구. 번역은 뒤에서 이어진다는 안내                                                        |
| 저장 완료 표시             | 저장 상태를 상위 컴포넌트에 둠(AI 판단)                                               | 저장 후 다시 불러온 값으로 폼을 다시 그려도 "저장했어요"가 남게 한다                            |

## 반영 내용

- `/admin/events`(상태·지역·출처·카테고리 필터, 행사명 검색, 더 보기), `/admin/events/new`, `/admin/events/:eventId`, 관리자 홈 "행사" 메뉴
- `event-api.ts`·`use-admin-events.ts`: 저장·삭제·수집 후 관리자 행사와 회원용 행사(`events`) 캐시 무효화
- `event-form.ts`: Zod(BE 길이 제한, 링크 형식, 날짜 하나 필수·순서, 지역 필수, 수정 시 날짜·시각·마감 비우기 금지), 한국 시간 변환, 바뀐 칸만 담는 수정 요청
- 상세: 출처·외부 ID·판 번호, en·zh·vi 번역 상태, 태그, 잠긴 칸(칸마다 "잠김" 표시), 삭제 확인
- 오류 문구 `EVENT_COLLECTION_RUNNING`(`DUPLICATE_EVENT`는 경고 화면으로 처리)
- MSW: 관리자 행사 API(바꿀 수 있는 목업 상태, 중복 판정, 잠금·판 번호, 수집 결과)
- 테스트: 폼 변환·검증·한국 시간, 계약(비관리자 403, 등록·중복 409·force·수정 잠금·검증·삭제·404, 수집)

| -------------------------- | ------------------- | -------------------------------------------------------------------------------------------- |
| 타입·린트·형식·Vitest·빌드 | `npm run check`     | 통과                                                                                         |

| 시각 비우기                | 목업 화면           | "이 칸은 비울 수 없어요"                                                                     |
| 수정                       | 목업 화면 요청 본문 | 장소 비우고 시작 시각 변경 → `{"venue":"","startsAt":"15:30"}`, 일정 변경 안내, 잠긴 칸 표시 |
| 등록 검증·중복             | 목업 화면           | 날짜 없음 → 폼 오류, 같은 행사 → 경고·링크 → "그래도 등록" → `?force=true` → 상세로 이동     |
| 삭제                       | 목업 화면           | 확인 후 목록, 상태 "삭제됨" 필터에서 열면 읽기 전용                                          |

| BE 계약 대조               | BE main 소스        | `AdminEventController`·요청/응답 DTO·`AdminEventService.update` 잠금 규칙과 일치             |
