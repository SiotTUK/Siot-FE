# 관리자 생활수칙·카테고리·FAQ 관리 화면 (ADM-06·RUL-04·09~13)

- 작성일: 2026-11-28
- 관련 이슈 / PR: SiotTUK/Siot-FE#43, BE PR(미생성)

## 목적

BE로 옮긴 생활수칙을 관리자 화면에서 등록·수정·삭제하고, 카테고리 이름·번역, 자주 묻는 질문(FAQ)을 관리한다.

## 핵심 요청

- 이슈 #43을 진행한다.
- 작업 전 확인한 차이와 사용자 결정
  - FAQ 관리에 필요한 관리자 API가 BE에 없다(`rule_faq`·`rule_faq_translation` 테이블과 회원용 `GET /api/rules/faq`만 있음). 사용자가 이번에 BE FAQ API도 추가하기로 했다.
  - 수정 폼을 채울 전체 값(문장 목록·출처 목록·확인일)을 읽는 관리자 API가 없다(목록은 요약만). 사용자가 BE에 관리자 상세 조회를 추가하기로 했다.
- 관리자 화면 문구는 한국어만 둔다(이슈에 명시).

## 선택과 이유

| 검토한 방법                         | 선택                                                        | 이유                                                                                            |
| ----------------------------------- | ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| FAQ 관리                            | BE API 추가(사용자 결정)                                    | 별도 이슈로 나누는 안 대신 이번에 함께 만든다                                                   |
| 생활수칙 상세 읽기                  | `GET /api/admin/rules/{code}` 추가(사용자 결정)             | 사용자용 API는 삭제한 항목을 못 읽고 관리자 화면이 회원 API에 기대게 된다                       |
| FAQ 번역                            | 관리자가 언어별로 직접 입력(AI 제안)                        | ko 필수, 나머지는 선택. 비운 언어는 회원 화면에서 한국어(BE 기존 동작). 자동 번역은 넣지 않았다 |
| FAQ 삭제                            | 실제 삭제(AI 제안)                                          | `rule_faq`에 삭제 표시 칸이 없고 다른 데이터가 FAQ를 가리키지 않는다                            |
| 본문(`content`)                     | 문장 목록에서 BE가 다시 만들게 `null`(AI 제안)              | 회원 화면은 문장 목록만 보여 준다. 문장을 고치고 옛 본문을 그대로 보내면 본문이 낡는다          |
| 폼에 없는 칸(배지·준비물·출처 이름) | 불러온 값 그대로 다시 보냄(AI 제안)                         | PUT이 모든 문구 칸을 바꾸므로 생략하면 지워진다                                                 |
| 안내 변경 알림                      | 저장 전에 "알림 보내고 저장 / 알림 없이 저장" 선택(AI 제안) | 이슈의 확인 단계. 체크박스보다 알림이 나간다는 사실을 저장 시점에 분명히 한다                   |
| 사람이 확인한 번역 보호             | BE 동작(`reviewed`) 그대로, 화면에 안내(AI 제안)            | BE #23: 한국어 저장 시 자동 번역만 다시 만든다. 문구 편집기에 자동/확인 번역 구분 표시          |
| 언어별 문구 수정                    | 기존 문구 편집기를 `?code=`로 열기(AI 제안)                 | 이슈의 "기존 체크리스트 문구 편집 재사용"                                                       |
| 저장 완료 표시                      | 저장 상태를 상위 컴포넌트에 둠(AI 판단)                     | 저장 후 다시 불러온 값으로 폼을 다시 그려도 "저장했어요"가 남게 한다                            |

## 반영 내용

BE(Siot-BE, 브랜치 `feat/admin-rule-detail-faq`)

- `GET /api/admin/rules/{code}`: 한국어 원문 전체(`RuleResponse`), 삭제한 생활수칙도 읽음, 생활수칙이 아니면 404
- `GET·POST /api/admin/rule-faqs`, `PUT·DELETE /api/admin/rule-faqs/{faqId}`: 언어별 질문·답변(ko 필수, 보내지 않은 언어는 지움), 연결 생활수칙(지운 항목 연결 불가, 연결 후 지우면 `ruleDeleted`), 순서
- 오류 코드 `RULE_FAQ_NOT_FOUND`(404), 통합 테스트 2개, `docs/api-admin.md`에 생활수칙·카테고리·FAQ API 정리

FE

- `/admin/rules`(카테고리 필터·검색·삭제 항목 포함, FAQ·번역 없음·삭제 표시), `/admin/rules/new`, `/admin/rules/:code`(수정·삭제 확인·삭제 항목 읽기 전용), `/admin/rule-categories`, `/admin/rule-faqs`, 관리자 홈 메뉴
- `rule-api.ts`·`use-admin-rules.ts`: 저장 후 관리자 생활수칙, 회원용 생활수칙(`rules`), 관리자 문구 편집기 캐시 무효화
- `rule-form.ts`: Zod(BE 길이 제한, 문장 1~30개, 출처 10개·링크 형식, 정렬 순서 숫자, 날짜), FAQ(ko 필수, 다른 언어는 질문·답변 둘 다 또는 비움)
- 문구 편집기: `?code=`로 바로 불러오기, 자동 번역/사람이 확인한 번역 안내
- 오류 문구 `DUPLICATE_GUIDE_CODE`·`RULE_CATEGORY_NOT_FOUND`·`RULE_FAQ_NOT_FOUND`
- MSW: 관리자 생활수칙·카테고리·FAQ API(바꿀 수 있는 목업 상태)
- 테스트: 폼 변환·검증, 계약(비관리자 403, 생활수칙 CRUD·중복 409·삭제 후 읽기, 카테고리 이름·번역·404, FAQ CRUD·검증·404)
