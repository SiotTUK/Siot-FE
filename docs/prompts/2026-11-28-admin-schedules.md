# 관리자 달력 공통 일정·세금 일정 관리 화면 (CAL-01~03·NTF-01)

- 작성일: 2026-11-28
- 관련 이슈 / PR: SiotTUK/Siot-FE#131, PR 미생성

## 목적

BE의 관리자 달력 일정 API 4개(`AdminScheduleController`)를 FE가 쓰지 않아 임시공휴일·기한 연장에 따른 마감일 수정, 정기분 밖 일정 등록, 잘못 만든 일정 끄기를 Swagger나 DB로만 할 수 있었다. 관리자 화면에서 할 수 있게 한다. BE 계약을 그대로 쓴다(BE 변경 없음).

## 핵심 요청

- 이슈 #131을 진행한다. 관리자 화면 문구는 한국어만 둔다(이슈에 명시).
- 이슈의 할 일: 목록(연도·종류 필터, 꺼 둔 일정·자동 생성 표시), 등록·수정 폼(끄기·켜기, 항목 목록에서 `guideCode` 고르기), 정기분 세금 일정 만들기와 결과, 관리자 첫 화면 메뉴 순서(#123 기준), MSW 목업·계약 테스트·비관리자 403

## 선택과 이유

| 검토한 방법                    | 선택                                                                              | 이유                                                                                                          |
| ------------------------------ | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 수정 화면에서 일정 불러오기    | 시작 연도를 주소에 두고(`/admin/schedules/:id?year=`) 그해 목록에서 찾음(AI 판단) | BE에 일정 하나를 읽는 API가 없다. 주소에 연도가 있어 새로고침·직접 열기도 된다                                |
| 목록 안에서 바로 고치기        | 제외(AI 판단)                                                                     | 행사·생활수칙처럼 목록 → 수정 화면으로 맞췄다                                                                 |
| 연도·종류 필터 위치            | 주소(`?year=&kind=`)(AI 판단)                                                     | 수정 화면의 뒤로 가기가 같은 연도 목록으로 돌아온다                                                           |
| 종류 필터 선택지               | 정기분 세금 3종 + 그해 목록에 있는 종류(AI 판단)                                  | `kind`는 자유 입력이라 고정 목록만으로는 `TAX_CAR_ANNUAL` 같은 종류를 고를 수 없다. 거르기는 서버 `kind`로 함 |
| 종류 입력                      | 글 칸 + 세금 3종 추천 목록(`datalist`), BE와 같은 형식 검사(AI 제안)              | 정기분 밖 일정의 종류도 넣을 수 있어야 한다. 서버 검증은 그대로 둠                                            |
| 연결 항목                      | `GET /api/admin/guides` 전체를 고르기, 생활수칙을 위에(AI 판단)                   | BE는 삭제되지 않은 모든 항목을 받는다. 세금 항목(`tax-car` 등)은 생활수칙이다                                 |
| 목록 제목                      | 연결 항목 제목, 없으면 종류 코드 그대로(AI 판단)                                  | 회원 달력도 같은 규칙(BE `CalendarScheduleService`)이라 관리자가 회원 화면 제목을 알 수 있다                  |
| 날짜 표시                      | 날짜마다 요일을 붙임(AI 제안)                                                     | `officialHolidays: false`일 때 주말·쉬는 날에 걸린 마감일을 찾기 쉽다                                         |
| 끄기                           | 스위치 + 저장, 끄면 "회원 달력과 세금 알림에서 빠져요" 안내(AI 제안)              | 지우는 API가 없다. 확인 창 대신 저장 전 안내로 충분하다고 봤다                                                |
| 정기분 만들기                  | 고른 연도로 바로 실행, 확인 창 없음(AI 판단)                                      | 없는 회차만 만들고 있는 회차는 건드리지 않아 여러 번 눌러도 같다                                              |
| `GUIDE_NOT_FOUND` 문구         | 이 화면에서만 관리자용 문구(AI 판단)                                              | 공통 문구는 회원용("이 안내를 찾을 수 없어요")이다                                                            |
| `SCHEDULE_NOT_FOUND` 공통 문구 | 추가하지 않고 이 화면에서만 처리(AI 판단)                                         | 관리자 문구는 한국어만이라 공통 오류 문구에 넣으면 회원 세금 상세 영어 화면에도 한국어가 보인다               |
| 메뉴 순서                      | 체크리스트 문구 다음, 챗봇 근거 문서 앞(AI 판단, 사용 기록 근거 아님)             | 정기분은 서버가 만들고 관리자는 1년에 몇 번 고친다. 문서 업로드·권한 지정보다는 잦다고 봤다                   |

## 반영 내용

- 화면: `/admin/schedules`(연도·종류 필터, 꺼 둠·자동 생성/직접 등록·세금 알림 표시, 등록·수정 관리자, 정기분 만들기), `/admin/schedules/new`, `/admin/schedules/:scheduleId?year=`, 관리자 첫 화면 "달력 일정" 메뉴
- 정기분 만들기 결과: 만든 회차(수정 화면 링크), 없으면 "새로 만들 회차가 없어요", `officialHolidays: false`면 마감일 확인 안내
- 수정 화면: 자동 생성 일정 안내, 세금 종류 안내(D-7·D-1 알림 대상), 끄기·켜기 안내, 저장 후 시작 연도가 바뀌면 주소의 연도도 바꿈
- `schedule-api.ts`·`use-admin-schedules.ts`: 저장·만들기 후 관리자 일정과 회원 달력(`schedules`)·세금 상세(`taxes`) 캐시 무효화
- `schedule-form.ts`: Zod(BE와 같은 종류 형식·길이, 시작일 필수, 마감일 ≥ 시작일, 링크 형식), 모든 값을 보내는 요청(PUT 덮어쓰기), 요일·기간 표시
- MSW `admin-schedules.ts`: 올해 정기분(하나는 관리자가 고침)·연납 신청 기간·꺼 둔 일정 시드, BE와 같은 검증 순서, 종류 거르기(연결 항목으로 같은 세금 포함), 정기분 만들기(주말·양력 고정 공휴일만 반영, `officialHolidays: false`)
- 공통 코드 변경: `src/mocks/db.ts`에 목업 상태 칸, `src/mocks/handlers/admin.ts`의 `isGuideCode` 내보내기, `src/app/router.tsx`에 경로 3개
- 테스트: 폼 검증·변환·표시, 계약(비로그인 401·비관리자 403, 연도 목록·정렬·종류 거르기·연도 범위, 등록 201·수정 덮어쓰기, 잘못된 입력 400·없는 항목 404·없는 일정 404, 정기분 만들기·다시 실행·꺼 둔 회차 다시 안 만듦)
