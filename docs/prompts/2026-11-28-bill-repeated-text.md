# 고지서 결과의 중복 표기 숨김

- 작성일: 2026-11-28
- 관련 이슈: [Siot-FE #28](https://github.com/SiotTUK/Siot-FE/issues/28), [#29](https://github.com/SiotTUK/Siot-FE/issues/29). PR은 미생성.
- 이전 기록: [챗봇 고지서 사진 번역](2026-11-28-chat-bill-translation.md)

## 목적

실기기에서 확인한 고지서 결과의 중복 표기를 없앤다. 납부 기한·금액의 둘째 줄과 납부 방법의 괄호가 대상이다. 납기 후 금액, 웹 주소, 이용 시간 같은 정보는 남긴다.

## 핵심 요청

- 첫 기준은 화면 언어가 한국어이거나 두 표기가 같으면 숨기는 것이다.
- 두 번째 기준은 둘째 줄이나 괄호 안에 한글이 없거나, 공백·기호를 빼고 번역값과 같으면 숨기는 것이다. 화면 언어로 판단하지 않는다.
- 최종 기준은 같은 값일 때만 숨기는 것이며, ‘한글이 없으면 숨김’은 뺀다. 사용자의 결정이다.
  - 기한: 항목 이름을 떼고 날짜로 읽었을 때 위 값과 같은 날짜이며 다른 글자가 없으면 숨긴다.
  - 금액: 항목 이름을 떼고 숫자가 위 값과 같으며 나머지가 단위(원, won, ₩, KRW)와 기호뿐이면 숨긴다.
  - 납부 방법: 괄호 안이 괄호 앞 이름과 같을 때만 괄호를 숨긴다. 공백과 대소문자는 무시한다.
  - 그 밖에는 모두 표시한다. ‘무엇인가요’ 항목은 바꾸지 않는다.
- #28 결과 화면과 #29 챗봇 결과 카드에 적용하고, 테스트와 한국어·영어 스크린샷을 추가한다. 후속 요청은 커밋·push와 PR 본문 준비다. PR은 생성하지 않는다.

## 선택과 이유

아래 선택은 AI가 정한 것이며 확인됨.

| 검토한 방법                                | 선택 | 이유                                                                                  |
| ------------------------------------------ | ---- | ------------------------------------------------------------------------------------- |
| 값이 없으면 둘째 줄 유지                   | 채택 | ‘읽지 못했다’는 안내가 사라지지 않게 한다.                                            |
| ‘무엇인가요’의 둘째 줄에도 기준 적용       | 제외 | 첫 줄이 한국어 세목 원문이라 둘째 줄이 번역이다. 적용하면 en·zh·vi의 설명이 사라진다. |
| 납부 방법의 문장·목록에는 괄호 기준만 적용 | 채택 | 위에 따로 표시하는 번역값이 없어 줄 자체가 본문이다.                                  |

두 번째 기준에서 검토한 ‘숫자 뒤의 원을 ₩로 처리’와 ‘한국어 날짜 문장을 뜻으로 비교하지 않음’은 최종 기준의 단위·날짜 판정으로 대체한다.

## 반영 내용

- 판정은 `bill-translation.ts`의 `billDueLine`, `billAmountLine`, `trimBillParentheses`에 둔다.
- 결과 화면은 기한·금액의 둘째 줄과, 납부 방법 문장·목록의 괄호에 적용한다. 챗봇 카드는 납부 방법의 괄호에 적용한다. 챗봇 카드의 기한·금액에는 원래 둘째 줄이 없다.
- 접어 둔 ‘원문 내용 대조’는 바꾸지 않는다.
- BE 프롬프트(`origin/main`의 `GeminiBillReader`)는 모든 언어의 납부 방법을 ‘요약 언어 이름 (한국어 서비스명)’으로 요청한다. BE는 수정하지 않는다.

최종 기준의 아래 세부 처리는 AI가 정한 것이며 확인됨.

- 항목 이름은 BE의 서버 요약과 FE 화면에서 쓰는 4개 언어 이름만 콜론 앞에서 뗀다. ‘납기 후 금액’ 같은 다른 이름은 남아 줄을 표시한다.
- 날짜는 연·월·일 숫자 표기(구분 기호, 년·월·일, 年·月·日)와 ko·en·zh·vi의 중간·긴 날짜 표기를 읽는다.
- 괄호 앞 이름은 단어 시작부터 괄호 직전까지의 글자와 비교한다. 문장 중간의 반복도 지운다.

## 검증

| 확인 항목 | 방법                                             | 결과                                                                                  |
| --------- | ------------------------------------------------ | ------------------------------------------------------------------------------------- |
| 전체 검사 | `npm run check`                                  | Vitest 44개 파일 482개 테스트와 빌드 통과. 500 kB 초과 청크 경고 표시.                |
| 결과 화면 | Chrome headless 390×844, MSW, ko·en 합성 번역 값 | 같은 값의 둘째 줄과 반복 괄호가 없고, 한글 은행 이름·웹 주소·이용 시간 괄호는 남는다. |
| 챗봇 카드 | 같은 목업의 카드 글자 확인                       | ko의 반복 괄호가 없다. en 확인 값의 납부 방법 문장에는 괄호가 없다.                   |

추가 정보가 있는 금액 줄(‘35,000 won after due date’)과 괄호 안 URL이 남는 것은 단위 테스트로 확인한다.

스크린샷: [한국어](assets/2026-11-28-bill-repeated-text-ko.png), [영어](assets/2026-11-28-bill-repeated-text-en.png). 번역 값은 `sessionStorage`의 목업 상태에만 넣으며 목업 코드는 바꾸지 않는다.

소문자 드라이브 경로(`c:`)에서 실행한 검사는 Vitest의 모든 파일이 ‘failed to find the runner’로 실패한다. 대문자 경로에서는 통과한다.

미검증: 실제 BE·Gemini, 실기기, zh·vi 화면.

## 2026-11-28 중국어·베트남어 금액 단위

- 후속 요청은 금액 단위에 韩元, 元, đồng, VND를 추가하고, 점(.)을 천 단위 구분으로 쓴 베트남어 금액도 비교하는 것이다. BE의 중국어 서버 요약 ‘缴纳金额：32,000韩元’이 남는 한계를 없앤다. 사용자의 결정이다.
- 단위 목록만 늘린다. 천 단위 점은 기존 숫자 비교가 이미 처리한다. ‘美元’처럼 다른 글자가 남거나 추가 설명이 있는 줄은 표시한다.
- `npm run check`는 Vitest 44개 파일 496개 테스트와 빌드를 포함해 통과한다. 500 kB 초과 청크 경고가 표시된다.
- 두 언어의 숨김은 단위 테스트로 확인한다. zh·vi 화면은 촬영하지 않으며, ko·en 스크린샷은 바꾸지 않는다.
