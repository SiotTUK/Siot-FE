# PC·모바일 브라우저와 기본 접근성 점검

- 작성일: 2026-11-28
- 관련 이슈 / PR: [#74](https://github.com/SiotTUK/Siot-FE/issues/74) / 미생성

## 목적

명세(NFR-01·04)의 PC·모바일 브라우저 지원과 레이블·상태 문구 인식 요건을 화면에서 확인한다. 지금까지 검증은 모바일 해상도 중심이라, PC 화면과 키보드·확대·긴 번역 조건의 결과를 남기고 주요 흐름을 막는 문제를 찾는다. 코드는 바꾸지 않는다.

## 핵심 요청

- #74를 진행한다. 범위는 홈·달력·행사·알림·챗봇·관리자 대표 흐름과 키보드·포커스·레이블·경고 문구·확대·긴 번역 잘림이다.
- 다른 브랜치(`feat/admin-menu-order`)에 커밋 전 변경이 있어, 최신 main(`2b1c474`)에서 별도 worktree와 브랜치(`test/issue-74-browser-a11y`)를 만들어 확인했다.

## 선택과 이유

| 검토한 방법                                          | 선택 | 이유                                                                                              |
| ---------------------------------------------------- | ---- | ------------------------------------------------------------------------------------------------- |
| 목업(`vite --mode mock`)으로 점검                    | 채택 | 화면 구조·키보드·레이블은 API와 무관하다. 관리자 흐름도 목업 계정으로 운영 데이터 없이 확인한다   |
| 배포 주소로 점검                                     | 제외 | 테스트 배포가 따로 없어 운영 데이터를 바꾸게 된다                                                 |
| 창 크기 대신 같은 출처 iframe 폭으로 뷰포트 재현     | 채택 | 확장 도구의 창 크기 변경이 적용되지 않았다. iframe 은 자체 뷰포트라 미디어 쿼리가 그대로 적용된다 |
| 확대를 CSS 폭으로 환산(1280 기준 200%=640, 400%=320) | 채택 | 도구로 브라우저 확대 단축키를 쓸 수 없다. WCAG 1.4.10 의 320 CSS px 기준과 같다                   |
| 별도 데스크톱 화면 구성                              | 보류 | PC 1440·640 폭에서 480px 앱 프레임이 막힘 없이 동작했다. 아래 문제를 고친 뒤 다시 판단한다        |

## 반영 내용

- 이 기록과 재현 화면 1장(`assets/2026-11-28-browser-a11y-focus-hidden.jpg`)만 추가한다. 코드 변경 없음.

## 검증

환경: Windows 11, Chrome 158(화면 배율 200%), 목업 서버, 목업 시드 계정(일반 회원·관리자). 실제 API·배포·실기기는 쓰지 않았다.

### 발견한 문제

| #   | 문제                                                            | 재현 경로                                                                                                                         | 영향                                                                                                             |
| --- | --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 1   | Tab 으로 이동한 요소가 하단 메뉴(`bottom-nav`, sticky)에 가려짐 | 홈을 맨 위에서 Tab 14번 → 두 번째 추천 카드의 찜 버튼(40px)이 메뉴 뒤에 전부 가려짐. 행사 목록도 카드 69/118px, 찜 30/40px 가려짐 | 키보드 사용자가 포커스 위치를 못 본다(WCAG 2.4.11). [재현 화면](assets/2026-11-28-browser-a11y-focus-hidden.jpg) |
| 2   | 요청 중 `disabled` 가 걸린 버튼에서 포커스가 `body` 로 빠짐     | 행사 상세 하단 찜 버튼에 Enter → 같은 버튼 요소인데 `document.activeElement` 가 `body`                                            | 다음 Tab 이 페이지 처음부터 시작한다. 같은 `disabled={…pending}` 패턴이 20곳(목록은 남은 작업)                   |
| 3   | 모든 화면의 문서 제목이 '웰컴시흥'으로 같음                     | 홈·달력·행사·알림·관리자 등 이동 후 `document.title`                                                                              | 탭 제목·화면 낭독기로 현재 화면을 구분하지 못한다(WCAG 2.4.2)                                                    |
| 4   | 320 폭에서 15px 가로 스크롤                                     | 자리를 차지하는 스크롤바(Windows 데스크톱) + 320 폭. 원인 `body { min-width: 320px }`                                             | PC 400% 확대에서만. 화면 위에 겹치는 스크롤바를 쓰는 모바일은 해당 없음                                          |
| 5   | 영어 챗봇 제목 말줄임                                           | 영어, 320 폭(스크롤바 포함) `/chat` → 'Welcome Siheung Helper' 가 5px 넘쳐 '…'                                                    | 같은 이름이 본문 첫 줄에 전부 나온다. 경미                                                                       |
| 6   | 글자 크기가 모두 px                                             | `src/styles.css` 의 `--text-*` 토큰과 CSS 의 `font-size` 60곳이 px                                                                | 페이지 확대는 되지만 브라우저 '글꼴 크기' 설정은 반영되지 않는다. 확대 차단(`user-scalable=no`)은 없음           |
| 7   | 홈에 `h1` 없음                                                  | `/home` 의 제목 구조                                                                                                              | 다른 화면은 `h1` 1개. 화면 낭독기의 제목 이동에서 홈 시작점이 없다. 경미                                         |

- 문제 1~3은 주요 흐름을 완전히 막지는 않지만 키보드·화면 낭독기 사용자의 조작을 방해한다. 4~7은 경미하다.
- 목업 알림 '시흥갯골축제 일정 변경'이 이름이 다른 목업 행사(`/events/2` '가족 과학 체험')로 연결된다. 목업 데이터끼리 맞지 않는 것이라 제품 문제에서 제외한다.

미검증:

- 관리자 행사 수정의 키보드 흐름: 진행 중 확장 도구의 키 입력이 페이지에 전달되지 않게 됐다(`keydown` 0건, 관리자 회원 화면도 같음). 앱의 전역 키 처리 코드는 찾지 못했다. 마우스 클릭으로는 수정 화면으로 이동한다.
- Safari·Firefox·Edge, iOS·Android 실기기, 실제 화면 낭독기(NVDA·VoiceOver) 낭독, 브라우저 확대 단축키 자체(폭 환산으로 대체), 실제 API·배포 환경.
