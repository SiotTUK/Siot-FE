# 챗봇 고지서 사진 번역

- 작성일: 2026-11-28
- 관련 이슈: [Siot-FE #29](https://github.com/SiotTUK/Siot-FE/issues/29). PR은 미생성.
- 이전 기록: [고지서 사진 번역](2026-11-27-bill-translation.md)

## 목적

챗봇 대화 안에서 고지서 사진을 번역하고, 결과에서 상세 화면으로 오갈 수 있게 한다.

## 핵심 요청

- 1단계에서 고지서 번역 부품을 분리한다. 2단계는 PR #89가 반영된 `origin/main`을 병합한 뒤 챗봇에 연결한다.
- 입력창 왼쪽 버튼과 첫 화면 칩에서 JPG·PNG 사진을 고르고, 동의 후 처리 중·결과·실패 카드를 표시한다.
- 카드 유지를 위해 번역 id와 대화 위치만 `sessionStorage`에 둔다. 로그아웃·계정 전환 시 지우고, 삭제된 번역은 짧게 안내한다.
- 챗봇에서 연 결과 화면의 뒤로 가기는 대화로 돌아간다.
- 4개 언어 문구와 테스트를 추가하고, 390×844 한국어 목업으로 확인한다. 구현 단계에서는 커밋과 push를 하지 않는다.
- 후속 요청은 vi·en 성공 결과 카드의 글자 넘침·잘림 확인, 재검사, 2단계 커밋과 push, PR 본문 준비다. PR은 사용자가 웹에서 생성한다.
- 이슈의 ‘이어서 묻기 칩’은 v2 시안에 없고 챗봇이 고지서 내용을 모르므로 제외하고 안내 문구를 둔다. 사용자의 결정이다.

## 선택과 이유

아래 선택은 AI가 구현 중 정한 것이며 확인됨.

| 검토한 방법                                 | 선택 | 이유                                                                                 |
| ------------------------------------------- | ---- | ------------------------------------------------------------------------------------ |
| 저장 값에 계정 구분용 `memberId` 포함       | 채택 | 현재 대화 저장과 같은 방식이며 다른 계정의 카드를 읽지 않는다.                       |
| 처리 중 질문 전송과 추가 사진 선택 비활성   | 채택 | 카드 위치를 마지막 메시지 기준으로 저장해 대화 순서를 유지한다.                      |
| 요청 오류도 실패 카드로 표시                | 채택 | 대화 안에서 상태를 보여 준다. 다시 시도는 동의를 새로 받으며 자동 재시도하지 않는다. |
| 처리 중·실패 카드는 저장하지 않음           | 채택 | 저장 대상은 번역 id가 있는 결과뿐이다. 새 질문을 보내면 실패 카드는 닫힌다.          |
| 상세 화면에서 새로 시작한 질문은 빈 새 대화 | 채택 | 이전의 미완성 새 대화에 있던 카드를 섞지 않는다.                                     |
| 저장 카드 수를 최근 20개로 제한             | 채택 | 저장 값이 계속 늘지 않게 한다.                                                       |

## 반영 내용

- `origin/main` `d460208`을 충돌 없이 병합한다. 병합 커밋은 `d110cb0`이다.
- 카드 저장·위치 계산은 `chat-bill-cards.ts`, 업로드 상태는 `use-chat-bill.ts`, 카드 UI는 `ui/chat-bill.tsx`에 둔다. 동의 시트, 처리 중 카드, 인식 실패 카드, 파일 입력은 1단계 부품을 사용한다.
- 새 대화에서 만든 카드는 첫 질문으로 대화가 생기면 그 대화 id에 연결한다. ‘새 대화’를 누르면 연결 전 카드를 지운다.
- 로그아웃, 로그인(계정 전환), 세션 만료 시 전체 카드를 지운다. 대화를 삭제하거나 찾을 수 없으면 그 대화의 카드를 지운다.
- 결과 카드 내용은 번역 id로 서버에서 다시 읽는다. 404면 삭제 안내를 표시한다. 카드가 늦게 로드되면 대화 끝으로 다시 스크롤한다. 이 보완은 새로고침 스크린샷에서 마지막 카드가 잘린 것을 확인한 뒤 추가한다.
- 공통 영역은 `use-session.ts`, `query-client.ts`에 카드 삭제를 추가하고, 번역 결과 화면의 뒤로 가기 경로를 바꾼다.

## 2026-11-28 PR 전 카드 문구와 요약 문장

- 요청 범위는 상세 버튼 문구를 시안의 ‘번역 결과 자세히 보기’로 바꾸고, 결과 필드로 만드는 고정 한 줄 요약을 4개 언어로 추가하는 것이다. 없는 값은 빼고 모두 없으면 문장을 생략하며, AI 호출은 추가하지 않는다. `.claude-docs/`는 `.gitignore`를 바꾸지 않고 로컬에서 제외한다.
- 아래 문장 규칙은 AI가 정한다. 서버의 `taxType`은 모든 언어에서 한국어이므로 쓰지 않는다. 납세고지서이거나 문서 종류가 없으면 `taxKind`의 세목 이름을 쓴다. 독촉장·체납액 고지서는 세목보다 문서 종류를 우선한다. ‘기타 문서’(`OTHER`)는 알려 주는 내용이 없어 이름을 생략한다. 기한이 올해(한국 날짜)가 아니면 연도를 함께 표시한다.
- `npm run check`는 Vitest 44개 파일 428개 테스트와 빌드를 포함해 통과한다.
- Chrome headless 390×844, MSW로 앞의 한국어 시나리오를 다시 실행해 통과한다. vi·en·zh의 성공 결과 카드에 글자 넘침·잘림이 없다. 위 스크린샷 중 성공, 대화 안의 카드, 상세에서 복귀를 새 화면으로 바꾼다.
- `.git/info/exclude`는 git에만 적용된다. Prettier는 `.claude-docs/`를 계속 검사한다.
- 기한이 지난 고지서도 요약 문장은 ‘…까지 내야 해요’이며, 지난 상태는 D-day 자리의 ‘기한 지남’으로 표시한다. 기한이 지난 화면은 촬영하지 않는다.

## 2026-11-28 기한 지난 고지서의 요약 문장

- 요약 문장 규칙(세목 이름, 독촉장·체납액 고지서 우선, ‘기타 문서’ 생략, 연도 표시)은 승인받는다.
- 후속 요청은 기한이 오늘보다 이전인 경우의 문장을 4개 언어로 바꾸는 것이다. 가산금처럼 데이터에 없는 내용은 넣지 않는다. 앞 절의 ‘…까지 내야 해요’ 처리를 대체한다.
- 한국 날짜로 기한 다음 날부터 ‘납부 기한 11월 1일이 지났어요’ 형태로 표시한다. 기한 당일은 기존 문장을 쓴다.
- AI 판단: 지난 경우에는 금액 문장을 넣지 않는다. 금액은 결과 카드의 납부 금액에 표시한다. 올해가 아닌 기한은 ‘2025년 11월 1일’처럼 연도를 풀어 쓴다. 기존 짧은 날짜는 마침표로 끝나 뒤에 문장을 이을 수 없기 때문이다.
- `npm run check`는 Vitest 44개 파일 434개 테스트와 빌드를 포함해 통과한다.
- 기한이 지난 고지서 화면은 목업에 해당 데이터가 없어 촬영하지 않는다. 문장은 단위 테스트로 확인한다.

## 남은 작업

- 처리 중 취소는 FE 요청만 중단한다. BE에는 취소 API가 없어 번역이 최근 기록에 남을 수 있으며, 취소한 결과는 대화에 추가하지 않는다.
- 새 대화의 첫 질문에 답이 오기 전에 상세 화면 등으로 이동하면, 연결 전 카드는 생성된 대화가 아닌 새 대화에 남는다.
