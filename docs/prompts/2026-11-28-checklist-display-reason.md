# 생활 변화 할 일에 보이는 이유 표시

- 작성일: 2026-11-28
- 관련 이슈 / PR: #137, #146. 관련 #31, BE SiotTUK/Siot-BE#45

## 목적

시안 v2 F06b(생활 변화 · 할 일)는 할 일 아래에 왜 보이는지("자차가 있어서 보여요")를 보여 준다. FE는 지금까지 서버에 이유 필드가 없어 분류(`category`)로 자동차·자녀만 추정해 보여 줬다. BE가 `reason`·`reasonLabel`을 주게 됐으니(BE #42, PR #45 merge) 서버 값으로 바꾼다.

## 핵심 요청

- 요약: 사용자가 #137(수지 님 배정)을 처리하자고 했다.

## 선택과 이유

| 검토한 방법                                    | 선택 | 이유                                                                                           |
| ---------------------------------------------- | ---- | ---------------------------------------------------------------------------------------------- |
| 서버 `reasonLabel`을 언어별 문장 틀에 넣기     | 채택 | 이슈의 계약. 이유는 서버가 정하고, 문장 틀만 FE 문구로 둔다                                    |
| 분류(`category`)로 자동차·자녀 추정(지금 코드) | 제외 | 이슈가 하지 말라고 했다. 서버가 주는 9가지 이유(취업·유학·F-4·체류 만료일 등)를 다 담지 못한다 |
| 맞춤 홈 줄에도 이유 표시                       | 보류 | 이슈의 "디자이너와 정한다" 항목. v2 홈은 생활 변화 칩만 있어 지금처럼 F06b에만 둔다            |
| 영어 문장 틀 "Shown {{reason}}"                | 제외 | 서버 영어 문구가 "Because you own a vehicle"처럼 대문자로 시작하는 완결된 절이라 그대로 쓴다   |

## 반영 내용

- `ChecklistItemResponse`에 `reason`·`reasonLabel`(선택, 예전 응답은 없을 수 있음).
- `reasonLine(t, item, shown)`: F06b에서 `reasonLabel`이 있으면 문장 틀(`checklist.reasonShown`)에 넣는다. ko "{이유} 보여요", en 서버 문구 그대로, zh "{이유}而显示", vi "{이유} nên hiển thị". 분류로 추정하던 `reasonOf`와 `checklist.reasons` 문구는 지웠다.
- MSW 목업: 목업의 표시 조건에 맞춰 BE와 같은 이유를 준다(체류기간 연장 STAY_EXPIRY, 거소 이전 F4, 자동차 주소 변경 CAR, 자녀 전학 KIDS, 고용센터·근무처 PURPOSE_WORK, 시간제 취업 PURPOSE_STUDY). 이름은 BE `ChecklistDisplayReason`과 같은 4개 언어.
