# 행사 목록 정렬·갱신 시각·필터 결과 없음·곧 시작·캐러셀 위치 점

- 작성일: 2026-11-28
- 관련 이슈 / PR: SiotTUK/Siot-FE#33

## 목적

피그마 M12·M13 행사 목록의 정렬, 갱신 시각, 수집 안내, 필터 결과 없음 화면을 BE API에 맞춰 넣는다. 이슈 댓글의 '곧 시작' 배지와 추천 캐러셀 위치 점도 함께 넣는다.

## 핵심 요청

- 이슈 #33을 진행한다. 팀 결정이 필요한 항목은 작업 전에 사용자에게 물었다.
- 사용자 결정
  - 정렬: BE가 지원하는 3가지(DATE·DEADLINE·LATEST)를 쓴다. 가까운순·추천순은 넣지 않는다.
  - 지역 필터: 이번에는 넣지 않는다.
  - 상단 칩: 지금 칩(진행중·예정·종료 + 분류 + 기간)을 유지한다.
  - 추가 범위: '곧 시작' 배지, 추천 캐러셀 위치 점을 넣는다.

## 선택과 이유

| 검토한 방법                                  | 선택                                                      | 이유                                                                                                                                                                                         |
| -------------------------------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 정렬 선택지 BE 3가지                         | 채택(사용자 결정)                                         | BE `sort=DATE\|DEADLINE\|LATEST`만 있다. 가까운순은 위치 정보, 추천순은 BE 지원이 없다                                                                                                       |
| 지역 필터                                    | 보류(사용자 결정)                                         | BE `region`은 SIHEUNG·GYEONGGI뿐이고 기본 공개 지역이 시흥 하나(`EVENT_PUBLIC_REGIONS`). 동 단위('정왕동 근처')는 BE에 없다                                                                  |
| v2 칩(전체·진행 중·곧 시작·무료·아이와 함께) | 제외(사용자 결정)                                         | 무료·아이와 함께는 BE 파라미터가 없다. 종료(지난 행사)가 지금 칩으로 동작한다                                                                                                                |
| 예정 행사에서 정렬 비활성                    | 채택(AI 제안)                                             | 예정 목록은 BE DATE 순서에서 진행 중/예정 경계를 찾아 FE가 나눈다(`event-list-page.ts`). 다른 순서에서는 나눌 수 없어 DATE만 쓰고 정렬 선택을 막는다. 기간 시작이 미래인 진행 중 목록도 같다 |
| 정렬은 필터가 아님                           | 채택(AI 제안)                                             | 필터 초기화·M13 초기화 뒤에도 정렬은 유지한다                                                                                                                                                |
| M13 초기화 범위                              | 채택(AI 제안)                                             | 분류·기간만 지우고 진행중/예정/종료와 정렬은 유지한다. M13 카드가 보일 때 위쪽 초기화 버튼은 숨긴다                                                                                          |
| 하단 수집 안내 문구                          | v2 문구 조정(AI 제안)                                     | v2 "경기도 문화행사 정보에서 가져와요"와 달리 BE는 GGC·TourAPI·전국축제 표준데이터 세 곳에서 수집한다. "경기도 문화행사 정보 등에서"로 쓴다. 새벽 3시는 BE `EVENT_COLLECT_CRON` 기본값       |
| '곧 시작' 기준 7일                           | 채택(사용자가 제안값 선택)                                | 시작일까지 7일 이내인 예정 행사. 홈 추천 카드에도 같이 적용된다                                                                                                                              |
| zh·vi '곧 시작' 문구                         | "7일 안에 시작"으로(AI 제안)                              | 기존 '예정' 번역(即将举行·Sắp diễn ra)과 '곧 시작' 직역이 거의 같은 뜻이라 구분되지 않는다                                                                                                   |
| 추천 카드(M12)                               | 1장 → 추천 전체를 옆으로 넘기는 캐러셀 + 위치 점(AI 제안) | 위치 점은 여러 장일 때만 의미가 있다. 점은 버튼이라 눌러 이동할 수 있다                                                                                                                      |

## 반영 내용

- 정렬: `EventListFilters.sort`(URL `sort`, 기본 DATE는 생략), 목록 제목 오른쪽 `EventSortSelect`. 지난 행사에서 DATE는 "최근 종료순"으로 표시
- 갱신 시각: `GET /api/events/collection-status` 연결, 제목 오른쪽 "갱신 11. 28. 03:00"(한국 시간). 성공한 수집이 없으면 숨긴다. 공통 `PageHeading`에 `aside` 추가
- 하단 수집 안내 문구
- M13: 분류·기간으로 좁힌 결과가 없으면 `StatusCard`(해로 + 제목 + 설명 + 필터 초기화)
- '곧 시작' 배지: `eventStatus`를 `event-display.ts`로 옮기고 `soon` 추가
- 추천 캐러셀 위치 점(M12)
- 4개 언어 문구, MSW(`sort` 처리, `collection-status`, 마감일 있는 목업 행사), 테스트
