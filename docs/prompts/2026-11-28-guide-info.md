# 관리자 항목 출처 링크·문의 전화 수정 (CHK-06·NTF-07)

- 작성일: 2026-11-28
- 관련 이슈 / PR: SiotTUK/Siot-FE#38, BE 조회 API PR(미생성)

## 목적

BE에 생긴 `PATCH /api/admin/guides/{code}`로 체크리스트·생활 변화 할 일·생활수칙 항목의 출처 링크(`sourceUrl`)와 문의 전화(`contact`)를 관리자 화면에서 바꾼다. 보내지 않은 값은 그대로, 빈 문자열은 지운다.

## 핵심 요청

- 이슈 #38을 진행한다.
- 작업 전 확인한 차이와 사용자 결정
  - 지금 값을 읽는 관리자 API가 없다(언어별 문구 GET에도 `sourceUrl`·항목 공통 `contact` 없음). 사용자가 처음에는 칸마다 "바꾸기" 체크 방식을 골랐다.
  - 이슈의 "4개 언어"는 README·`admin/messages.ts`의 관리자 화면 한국어 전용 규칙과 다르다. 사용자가 한국어만 두기로 했다.
- 후속 요청(같은 날): 체크 방식 구현 후, 사용자가 BE에 조회 API를 추가하기로 했다. BE에 `GET /api/admin/guides/{code}`를 만들고 FE는 지금 값을 채워 보여 주는 방식으로 바꿨다.

## 선택과 이유

### 1차: 조회 API 없이 (체크 방식, 후속 요청으로 대체)

| 검토한 방법                 | 선택                                               | 이유                                                                                         |
| --------------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 칸마다 "바꾸기" 체크        | 채택(사용자 결정) → 후속에서 대체                  | 체크 안 함 = 생략(그대로), 체크하고 비움 = `""`(지우기). 지금 값을 몰라도 두 경우를 구분한다 |
| BE에 조회 API 추가 요청     | 제외(사용자 결정) → 후속에서 채택                  | 처음에는 FE만 범위로 했다                                                                    |
| 사용자용 API로 지금 값 표시 | 제외(사용자 결정)                                  | 생활 변화 할 일은 값이 없을 수 있고, 관리자 화면이 사용자 API에 기대게 된다                  |
| 지금 값 확인                | 저장 응답으로 표시(AI 제안)                        | 빈 PATCH로 읽으면 `updatedAt`·`updatedBy`가 바뀌어 쓰지 않는다                               |
| 저장 후 캐시                | 체크리스트·생활 변화·생활수칙 전체 무효화(AI 제안) | 응답 `kind`와 상관없이 같은 값을 보여 주는 화면을 모두 새로 받는다(후속에도 유지)            |

### 2차: BE 조회 API 추가 후

| 검토한 방법             | 선택                                          | 이유                                                                                |
| ----------------------- | --------------------------------------------- | ----------------------------------------------------------------------------------- |
| 조회 경로               | `GET /api/admin/guides/{code}`(AI 제안)       | PATCH와 같은 경로·같은 응답(`GuideInfoResponse`). 조회는 수정 기록을 남기지 않는다  |
| 바꾸지 않음·지우기 구분 | 불러온 값과 비교해 바뀐 칸만 보냄(AI 제안)    | 그대로인 칸은 생략, 비운 칸은 `""`. 체크 없이도 구분된다                            |
| 아무것도 안 바꾼 저장   | 폼 오류 "바뀐 값이 없어요"(AI 제안)           | 수정 시각만 바뀌는 요청을 막는다                                                    |
| 저장 완료 표시          | 저장 상태를 상위에 두고 "저장했어요"(AI 판단) | 저장 후 새 값으로 칸을 다시 그려도 안내가 남게 한다. 값을 다시 고치면 안내를 숨긴다 |

## 반영 내용

BE(Siot-BE, 브랜치 `feat/admin-guide-info-get`)

- `GET /api/admin/guides/{code}`(`AdminGuideService.getInfo`, 관리자 전용, `GUIDE_NOT_FOUND`)
- 통합 테스트(값 조회, 지운 값 빠짐, 조회가 `updated_at`을 바꾸지 않음, 404, 일반 회원 403), `docs/api-admin.md`에 GET·PATCH 추가

FE

- `fetchGuideInfo`·`updateGuideInfo`, `GuideInfoResponse`·`GuideInfoUpdateRequest` 타입, `adminKeys.guideInfo`
- `useGuideInfo`, `useUpdateGuideInfo`(저장 응답을 조회 캐시에 넣고 `checklist`·`life-changes`·`rules` 쿼리 무효화)
- `guide-info-form.ts`: Zod 스키마(링크 형식·길이), 불러온 값과 비교해 바뀐 칸만 담는 요청 변환
- 관리자 문구 편집 화면 위 "출처 링크 · 문의 전화 (모든 언어 공통)": 지금 값을 채운 입력란, 마지막 수정 시각, 저장 완료 안내
- 한국어 문구(관리자 전용)
- MSW: GET·PATCH(관리자 전용, 형식·길이 검증, 생략 유지·빈 문자열 삭제, `GUIDE_NOT_FOUND`), CL-01 시드 값, 바꾼 값을 체크리스트 목업 응답에 반영
- 테스트: 폼 변환·검증, 계약(비관리자 403, 조회, 저장·지우기, 잘못된 링크 400, 없는 항목 404)
