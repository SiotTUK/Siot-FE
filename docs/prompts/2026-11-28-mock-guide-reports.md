# 체크리스트·생활 변화 할 일 오류 신고: 목업 404와 사유 코드 수정

- 작성일: 2026-11-28
- 관련 이슈 / PR: [#135](https://github.com/SiotTUK/Siot-FE/issues/135) / [#138](https://github.com/SiotTUK/Siot-FE/pull/138). 이전 기록: [2026-11-28-admin-reports.md](2026-11-28-admin-reports.md) 남은 작업

## 목적

목업 `POST /api/reports` 가 체크리스트(`CL-01`)·생활 변화 할 일(`LC-01-1`) 코드 신고를 404 `GUIDE_NOT_FOUND` 로 거절한다. 실제 BE는 종류와 상관없이 코드로 받는다. 목업이 관리자 목록에 남기는 신고도 대상 종류를 모두 `RULE` 로 적는다. 이를 BE와 같게 맞춘다.

## 핵심 요청

- #135를 고친다. 이슈 범위는 목업 수락, 관리자 목록의 대상 종류·제목, "신고 대상 열어서 고치기" 경로, 계약 테스트다.
- 작업 중 운영 코드 문제를 함께 발견해 같은 PR에서 고쳤다. 체크리스트 신고 요청이 사유를 한국어(`'내용 오류'` 등)로 보낸다. BE `ContentReportRequest.reason` 은 `TRANSLATION|CONTENT|OTHER` 만 받는다. 목업도 같은 검사를 하므로 404를 고쳐도 400 `INVALID_INPUT` 에 막힌다.

## 선택과 이유

| 검토한 방법                                                  | 선택 | 이유                                                                                                |
| ------------------------------------------------------------ | ---- | --------------------------------------------------------------------------------------------------- |
| 목업이 생활수칙 다음 `mockGuideSummaries()` 에서 코드를 찾음 | 채택 | 관리자 항목 목록(CHK-06)과 같은 목록이라 코드·종류·한국어 제목이 한곳에 있다                        |
| `recordReport` 가 대상 종류를 인자로 받음                    | 채택 | 종류는 코드를 찾은 쪽(신고 처리기)이 안다. `targetType` 은 BE처럼 안내 항목이면 모두 `RULE` 로 둔다 |
| 체크리스트 사유를 생활수칙·행사 신고처럼 API 코드로 보냄     | 채택 | BE 계약(`REASON_PATTERN`)과 다른 두 신고 기능이 이미 코드로 보낸다                                  |
| 사유 수정을 별도 이슈로 분리                                 | 제외 | #135의 체크리스트 신고 흐름이 같은 문제로 막힌다. 한 파일 몇 줄이라 함께 고쳤다                     |

## 반영 내용

- `src/mocks/handlers/events.ts`: `reportedGuide(code)` 가 생활수칙 → 체크리스트·생활 변화 할 일 순으로 코드를 찾아 종류와 한국어 제목을 돌려준다. 없으면 404 `GUIDE_NOT_FOUND`. 코드 앞뒤 공백은 BE처럼 무시한다.
- `src/mocks/handlers/admin-reports.ts`: `recordReport` 가 `targetKind` 를 받아 `CHECKLIST`·`LIFE_CHANGE_TASK`·`RULE`·`EVENT` 로 저장한다.
- `src/features/checklist/checklist-report.ts`: 사유를 `TRANSLATION`·`CONTENT`·`OTHER` 로 보낸다(운영 코드).
- `src/features/checklist/checklist-report.test.ts`: 기존 요청 본문 테스트의 사유 기대값을 `CONTENT` 로 바꾸고, 목업 계약 테스트를 추가했다(`CL-01`·`LC-01-1` 201, `CL-99` 404, 관리자 목록의 종류·제목·수정 화면 경로).
