# 실제 서버 체류 만료 알림 확인

- 작성일: 2026-11-28
- 관련 이슈 / PR: #25(merge됨) 후속. 이전 기록: [2026-11-26-notifications.md](2026-11-26-notifications.md)

## 목적

PR #25는 목업으로만 알림 목록·배지·읽음·이동을 확인하고 merge되었다(이전 기록의 남은 작업 "실제 BE로 목록·개수·읽음 확인"). 실제 BE가 매일 오전 9시에 만드는 체류 만료 알림으로 같은 동작을 확인하고 결과와 화면을 남긴다. 코드는 바꾸지 않는다.

## 핵심 요청

- 요약: 11/27에 사용자가 테스트 회원의 체류 만료일과 생활 마감 알림을 설정해 두고, 11/28 오전 9시 알림 작업 뒤에 실제 알림을 확인하기로 했다. 확인 후 사용자가 결과와 스크린샷을 PR #25에 남기자고 했다.
- 후속: #25가 이미 merge되어 사용자가 새 docs PR로 기록·화면을 올리고 #25에 결과 댓글을 다는 방법을 골랐다.

## 선택과 이유

| 검토한 방법                         | 선택 | 이유                                                          |
| ----------------------------------- | ---- | ------------------------------------------------------------- |
| merge된 #25 브랜치에 커밋 추가      | 제외 | merge된 PR에 붙지 않는다                                      |
| 새 docs PR에 기록·화면 + #25에 댓글 | 채택 | 화면을 저장소에 남기고 #25에서 바로 찾을 수 있다(사용자 결정) |
| #25에 글 댓글만                     | 제외 | CLI로 댓글에 이미지를 올릴 수 없어 화면이 남지 않는다         |

## 반영 내용

- 이 기록과 실제 서버 화면 3장(`assets/2026-11-28-notifications-real-*.png`)만 추가한다. 코드 변경 없음.

## 검증

실제 서버(개발 서버 5173 → 실제 BE), 테스트 회원(일반 권한, 회원 언어 영어), 390 너비 브라우저. 화면은 #25 코드가 들어 있는 작업 브랜치(`feature/home/figma-v2`)로 띄웠다. main의 #107(알림 후속) 변경 전 화면이다.

| 확인 항목           | 방법                                | 결과                                                                                                                         |
| ------------------- | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 알림 생성           | `GET /api/members/me/notifications` | 1건. `kind: STAY_EXPIRY`, `linkType: CALENDAR`, `status: SENT`, `emailStatus: SENT`, `locale: en`. 09:00 예약, 09:00:31 발송 |
| 탑바 배지           | 홈·알림 화면                        | 종 옆 "1", 안 읽은 개수 API 1                                                                                                |
| 목록 표시           | `/notifications`                    | "Deadline · Today" 표시, 안 읽음 점, 제목 "Stay expiry in 14 day(s)"                                                         |
| 누르면 읽음 후 이동 | 알림 카드 클릭, 네트워크 기록       | `PATCH …/notifications/1/read` 200 뒤 `/calendar`로 이동                                                                     |
| 배지 감소           | 이동 후 화면·API                    | 배지 사라짐, 안 읽은 개수 0, `read: true`·`readAt` 저장                                                                      |

- 알림은 계획한 D-7이 아니라 D-14로 왔다. 확인 시점에 테스트 회원의 체류 만료일이 11/27에 넣은 날짜가 아니라 12월 12일이었고, 14일 전 알림도 켜져 있어 그 기준으로 정상 발송되었다. 날짜가 바뀐 경위는 미확인이다.
- 화면의 언어 선택이 영어 화면에서도 "한국어"로 보이는 것은 #84에서 고친 문제다. 촬영한 브랜치에 그 수정이 없다.

미검증: 이메일 실제 수신함 확인(서버 `emailStatus: SENT`만 확인), 중국어·베트남어 알림 문구, 읽음 실패 상황.
